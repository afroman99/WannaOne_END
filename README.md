# WannaOne_END

연주 설비(`P1-CC1-INS01`) 센서 데이터로 **24시간 안 고장 여부를 미리 알리는 조기경보** 모델을 만든다.

현재 단계: 데이터 준비, EDA, 기준 예제 재현, 전처리·특징, 평가 함수, 조기경보 모델(검증 세트 평가), 테스트 세트 예측, 문제정의서·결과보고서 완료 → 팀 결정 A~G 확정, 발표자료 예정

## 실행 방법

### 1. 데이터 변환 (처음 한 번만)

원본 데이터 폴더(`POSKO-PdM-Data-pdm-v2.2.0`)를 받은 뒤, 프로젝트 루트에서 실행한다.

```bash
python -m src.posko_data --src <원본 폴더 경로>
```

- 원본은 해시 이름의 CSV 조각 6천여 개로 나뉘어 있다. 이 명령이 원자료 종류별 Parquet 파일 하나로 합쳐 `data/posko/`에 저장한다(약 5분, 5.4GB → 950MB).
- 행 수와 SHA-256을 원본 `manifest.json`과 대조해 검사한다.

### 2. 분석 실행

```bash
python analysis/01_eda.py
python analysis/02_baseline.py
python analysis/03_check_features.py
python analysis/04_model.py
python analysis/05_predict_test.py
python analysis/06_caution.py
python analysis/07_cause_part.py
```

| 스크립트 | 하는 일 | 시간 |
|---|---|---|
| `01_eda.py` | EDA 1~11절 재계산, 그림 10장 저장 | 약 20초 |
| `02_baseline.py` | 데이터셋 기준 예제 재현과 오류 분석 | 약 20초 |
| `03_check_features.py` | 전처리·특징 점검 21개 항목 (`--quick`이면 누설 검사를 표본 100개로) | 약 3분 (`--quick` 20초) |
| `04_model.py` | **메인**: 학습 세트 교차검증으로 모델·임계값 선택, 검증 세트 한 번 평가, 근거 그림 4장 | 약 1분 |
| `05_predict_test.py` | 검증한 모델(경보·주의)로 테스트 세트 예측 → `predictions/test_risk24.csv`, 모델 저장 | 약 30초 |
| `06_caution.py` | 2단계 경보의 주의 기준을 학습 세트 교차검증으로 정하고 검증 세트에서 확인, 근거 그림 2장 | 약 1분 |
| `07_cause_part.py` | 원인 부품을 5초 원자료 파형·정비 기록으로 구분할 수 있는지 확인, 근거 그림 1장 (`05_predict_test.py`를 먼저 실행) | 약 1분 |

- 필요한 패키지: pandas, numpy, pyarrow, matplotlib, scikit-learn (Python 3.14, pandas 3.0, scikit-learn 1.9에서 확인)
- 프로젝트 루트에서 실행한다. 그림은 `figures/`에 저장된다(저장소에는 올리지 않음).
- `05_predict_test.py`는 학습한 모델을 `models/risk24.joblib`에 저장한다(저장소에는 올리지 않음). 대시보드가 이 파일을 쓴다.
- 그래프 한글 글꼴은 `src/plotting.py`가 설치된 글꼴에서 고른다(macOS AppleGothic → Windows 맑은 고딕 → 나눔고딕). 셋 다 없으면 경고가 나오니 나눔고딕을 설치한다. 그림 파일 이름은 Windows에서도 한글이 깨지지 않게 NFC로 저장한다.
- 전처리 코드를 고치면 `03_check_features.py`를 다시 실행해 모두 통과하는지 확인한다.

## 데이터 출처

- POSKO 예측정비 **합성 데이터** `pdm-v2.2.0` (교육용 배포본). 실제 조업 데이터가 아니다. 결과는 설비 특성이 아니라 데이터 생성 규칙을 반영한다.
- 72시간짜리 독립 시나리오 360개. 시작 시각 순서로 분할돼 있다.

| 분할 | 시나리오 | 정답 | 용도 |

| 학습 | 216개 (`S0001`~`S0216`) | 있음 | EDA, 특징 설계, 모델·임계값 선택(교차검증) |
| 검증 | 72개 (`S0217`~`S0288`) | 있음 | 최종 평가 (한 번만) |
| 테스트 | 72개 (`S0289`~`S0360`) | 없음 | 최종 예측 |

- 사용하는 파일 (`data/posko/`, 용량 문제로 저장소에는 올리지 않음)

| 파일 | 내용 |
|---|---|
| `raw/casting.parquet` | 연주 센서 원자료 (5초 간격, 1,866만 행) |

- **지키는 규칙**
  - EDA·특징 설계·모델 선택은 학습 세트로만 한다. 검증 세트는 마지막에 한 번만 본다.
  - 정답 열과 예측 시점 이후 정보(센서·정비)는 특징으로 쓰지 않는다. `03_check_features.py`가 원자료를 예측 시점에서 잘라 다시 계산해 확인한다.
  - 검열된 정답은 0으로 채우지 않고 뺀다.

## 분석 요약

**EDA 주요 결론** (학습 세트 216개 시나리오)
- 고장은 51건이다. **점진 고장 45건**은 열화가 14.5~54.5시간 이어진 뒤 고장 나고, **돌발 고장 6건**은 신호 없이 갑자기 고장 난다. 진단 정답의 `failed` 구간만 보면 6건만 보이므로, 고장 여부는 정비 기록의 `FAILURE_DT`로 판단한다.
- 열화 신호 4개: `MLD-LVL` 진폭, `CONTROL_DELAY`, `WD-LOD`(부하 보정)는 커지고 `OSC-STK`는 작아진다. **고장 24~36시간 전부터** 정상과 갈린다.
- 24시간 앞서 잡을 수 있는 고장의 상한은 약 76%(39/51건)다.
- 네 신호를 정상 분포로 표준화한 **평균 점수**는 정상 구간의 경계 초과 비율을 5%에서 0.4%로 줄이면서 고장 전 감지 비율 79%를 유지한다.
- 센서로 고장 원인(마찰·고착·제어 지연)은 구분할 수 없다. 그래서 **원인과 상관없이 24시간 안 고장 여부**를 예측한다. 5초 원자료의 파형으로도 구분되지 않았다(`07_cause_part.py`).
- 정비 후에도 신호가 처음 수준까지 돌아가지 않는다. 그래서 재가동 기준과 처음 수준 기준 변화량을 함께 쓴다.

**평가 기준과 팀 결정** (모두 확정. 결정마다 근거는 `reports/연주_조기경보_모델_결과.md` 3-4절)
- 원칙: 평가는 결과를 부풀리지 않게, 경보는 미탐을 줄이는 쪽으로. 비용 규칙상 고장을 놓치면 66점, 오경보는 28~48점이다.
- 모델·특징·임계값은 모두 학습 세트 교차검증(보정값도 폴드마다 다시 정함)으로 정한다. 모델은 교차검증 AP로 고르고, 임계값은 **점진 고장을 모두 잡고 진짜 오경보가 0인 임계값 중 가장 낮은 것**(오경보 없이 가장 일찍 경보)으로 정한다.
- 대표 숫자는 이른 경보도 오경보로 센다. 재현율은 신호가 없는 돌발 고장을 빼고 점진 고장 기준으로 보고하되, 돌발 고장을 포함한 값도 함께 적는다. 원인 부품은 데이터로 알 수 없으므로 경보가 나면 "두 부품 모두 교체"한다("항상 밸브만 교체"는 944~968점으로 더 비쌈).
- 시간을 세는 특징(경과 시간, 재가동 후 시간)은 쓰지 않는다. 관측 끝 시점은 정답이 모두 "고장"이라 "오래 돌았으면 고장"이라는 착시를 배운다.
- 정답을 알 수 없는 관측 끝부분의 경보는 **미확정 경보**로 따로 세어 운영 비용에 범위로 더한다.

**개정 (외부 검토 반영)**: 이전 모델(로지스틱 회귀, 임계값 0.76)이 재가동 후 시간(`SEG_HOURS`)으로 위 착시를 배워, 관측 끝부분에서 멀쩡한 설비에도 경보를 울린 것을 찾아 고쳤다. 그래서 최종 모델이 **랜덤포레스트, 임계값 0.67**로 바뀌었다. 바뀐 이유는 모델 결과 문서 앞부분의 개정 내역과 3-4절 D에 있다.

- **비용 효과는 원인 부품을 알 수 있느냐에 달려 있다.** 둘 중 하나를 찍어 교체하면 아무것도 안 할 때와 비용이 거의 같다.

**테스트 세트 예측** (`predictions/test_risk24.csv`)
- 검증 세트에서 평가한 모델(학습 세트로 학습, 임계값 0.67)을 그대로 쓴다.
- 예측 시점은 시나리오마다 0~66시간 6시간 간격에서 정비 중인 시점을 뺀 것이다. 이 규칙은 학습·검증 세트에서 정답 파일의 `AT_RISK=1`과 정확히 일치한다.
- 72개 시나리오, 833개 시점 중 경보 83개(10.0%), 경보가 난 시나리오 18개. 검증 세트 경보 비율(11.4%)과 비슷하다.
- 데이터셋 앱용 예측 JSON은 받은 데이터에 없는 '관측 교환본'의 해시 값이 필요해 CSV로 저장했다.

**2단계 경보: 주의 단계** (`analysis/06_caution.py`, 결과보고서 7-5절)
- 현장에서는 부품 조달 때문에 24시간 경보도 빠듯하다. 그래서 경보보다 먼저 켜지는 주의 단계를 둔다.
- 주의의 정답은 "지금 열화 중인가"(진단 정답의 열화 구간)다. 경보 모델의 기준만 낮추면 경보보다 평균 6시간밖에 먼저 켜지지 않아서, **열화 감지 모델(랜덤포레스트 · 센서)**을 따로 두었다.
- 기준: 주의 중 85% 이상은 실제로 열화 중인 설비(정밀도 ≥ 0.85). 그 안에서 가장 낮은 값 **0.38**을 학습 세트 교차검증으로 골랐다. 현장에서는 주의를 받으면 장비 상태를 확인하고 다음 정비 때 함께 정비하므로, 헛걸음 비용이 점검 한 번이라 헛걸음을 조금 허용한다(처음 0.9에서 낮춤).

| | 학습 세트 교차검증 | 검증 세트 |
|---|---|---|
| 주의 정밀도 | 0.859 | 0.774 |
| 주의로 감지한 점진 고장 | 45/45 | 14/14 |
| 경보보다 먼저 켜진 시간 (평균 / 중앙값) | 13.5 / 12시간 | 12.4 / 12시간 |

- 검증 세트 정밀도는 목표에 못 미쳤다. 헛걸음 7번 중 4번은 열화 시작 직전, 3번은 정상 설비였다.

**원인 부품 구분** (`analysis/07_cause_part.py`, 결과보고서 6-1절)
- 5초 원자료의 파형 특징 182개로도 부품은 구분되지 않는다. 같은 고장 모드끼리 보면 교차검증 AUC 0.40(찍기 0.5)이고, 라벨을 섞었을 때와 차이가 없다. 전체에서 AUC가 0.64로 보인 것은 부품이 아니라 열화의 심각도를 맞힌 착시였다.
- 정비 기록에서는 "직전 정비가 부분 정비였으면 다음 고장은 그 부품"이었다(학습 6/6, 검증 2/2). 하지만 이 데이터에서는 부분 정비가 모두 하루쯤 뒤 같은 부품의 고장으로 이어진다. 현장에서는 제대로 된 부분 정비 뒤 재고장이 드물고, 재고장은 정비 불량이나 부품 불량일 때뿐이다. 그래서 합성 데이터의 성질로 보고 결정 C(두 부품 교체)는 그대로 둔다.

## 추가 시도: 조기경보 대시보드 (정건우)

> 팀 과제 범위 밖에서 개인적으로 추가로 해 보고 싶은 작업이다. 모델을 서비스 형태로 쓰면 어떤 모습일지 보여 주는 시연용이다.

```bash
pip install streamlit
python analysis/05_predict_test.py      # 처음 한 번: 모델 학습·저장
streamlit run app/dashboard.py          # 브라우저에서 http://localhost:8501
```

| 화면 | 내용 |
|---|---|
| 전체 현황 | 설비(시나리오)별 지금 단계(경보·주의·정상·정비 중), 위험한 순서, **부품 소요 예측**(경보 설비 = 지금 교체, 주의 설비 = 1~2일 안에 필요할 수 있음. 두 부품 모두 교체 기준) |
| 설비 상세 | 24시간 고장 확률·열화 확률과 네 신호의 흐름, 정비·고장 기록, 지금 신호 상태, 단계별 조치 안내(주의: 장비 점검 → 다음 정비 때 함께 정비, 재고 확인) |
| 모델 정보 | 경보·주의 모델과 기준, 검증 세트 성능, 고장별 결과 |
| 비용 계산기 | 원인 부품을 맞힐 확률에 따른 비용 (팀 결정 C). 0.67 이상 맞히면 한 부품만 바꾸는 쪽이 쌈. 미확정 경보 비용도 함께 표시 |

- **실시간이 아니라 재생 방식**이다. 사이드바의 '지금 시각'을 옮기면 그 시각까지의 데이터만으로 본 상태를 보여 준다.
- 저장된 모델로 예측만 한다. 특징은 예측 시점까지의 정보만 쓰므로(`03_check_features.py` 누설 검사), 실제 데이터가 들어오는 상황에서도 같은 결과가 나오는 구조다. 실시간으로 바꾸려면 `src/serving.py`의 원자료 읽기만 새 데이터로 바꾸면 된다.
- 검증 세트를 고르면 실제 고장 시각(정답)을 겹쳐 볼 수 있다. 모델은 이 정보를 보지 않는다.
- 2단계 경보: `05_predict_test.py`가 경보 모델과 함께 주의 모델(열화 감지, 기준 0.38)을 학습해 `models/risk24.joblib`에 저장한다. 예전에 저장한 모델 파일이면 주의 단계 없이 경보만 보여 주니 `05_predict_test.py`를 다시 실행한다.
