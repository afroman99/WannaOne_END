# WannaOne_END

연주 설비(`P1-CC1-INS01`) 센서 데이터로 **24시간 안 고장 여부를 미리 알리는 조기경보** 모델을 만든다.

현재 단계: 데이터 준비, EDA, 기준 예제 재현 완료 → 전처리·특징 만들기 예정

## 실행 방법

### 1. 데이터 변환 (처음 한 번만)

원본 데이터 폴더(`POSKO-PdM-Data-pdm-v2.2.0`)를 받은 뒤, 프로젝트 루트에서 실행한다.

```bash
python -m src.posko_data --src <원본 폴더 경로>
```

- 원본은 해시 이름의 CSV 조각 6천여 개로 나뉘어 있다. 이 명령이 원자료 종류별 Parquet 파일 하나로 합쳐 `data/posko/`에 저장한다(약 5분, 5.4GB → 950MB).
- 행 수와 SHA-256을 원본 `manifest.json`과 대조해 검사한다.

### 2. 분석 실행

```bash
python analysis/01_eda.py
python analysis/02_baseline.py
```

- 필요한 패키지: pandas, numpy, pyarrow, matplotlib, scikit-learn (Python 3.14, pandas 3.0, scikit-learn 1.9에서 확인)
- 프로젝트 루트에서 실행한다. 그림은 `figures/`에 저장된다(저장소에는 올리지 않음).
- 그래프 한글 글꼴로 macOS 기본 글꼴(AppleGothic)을 쓴다.

## 데이터 출처

- POSKO 예측정비 **합성 데이터** `pdm-v2.2.0` (교육용 배포본). 실제 조업 데이터가 아니다. 결과는 설비 특성이 아니라 데이터 생성 규칙을 반영한다.
- 72시간짜리 독립 시나리오 360개. 시작 시각 순서로 분할돼 있다.

| 분할 | 시나리오 | 정답 | 용도 |
|---|---|---|---|
| 학습 | 216개 (`S0001`~`S0216`) | 있음 | EDA, 특징 설계, 모델 학습 |
| 검증 | 72개 (`S0217`~`S0288`) | 있음 | 모델 비교, 임계값 결정 |
| 테스트 | 72개 (`S0289`~`S0360`) | 없음 | 최종 예측 |

- 사용하는 파일 (`data/posko/`, 용량 문제로 저장소에는 올리지 않음)

| 파일 | 내용 |
|---|---|
| `raw/casting.parquet` | 연주 센서 원자료 (5초 간격, 1,866만 행) |
| `raw/maintenance.parquet`, `raw/calendar.parquet` | 정비 기록, 정기수리 계획 |
| `raw/events.parquet` | 운전조건 변경 |
| `labels.parquet` | 6·24시간 고장 위험 정답 (6시간마다) |
| `diagnostics.parquet` | 상태 구간(정상·열화·고장·정비)과 원인 |
| `targets.parquet` | 잔여수명, 교체 정책 정답 |

- **지키는 규칙**: EDA·특징 설계는 학습 세트로만 한다. 정답 열과 예측 시점 이후 정보는 특징으로 쓰지 않는다. 검열된 정답은 0으로 채우지 않고 뺀다.

## 폴더 구성

```
src/
  posko_data.py      원본 → Parquet 변환, 불러오기 함수 (load_source, load_answer, load_scenarios)
analysis/
  01_eda.py          EDA: 데이터 품질, 열화 신호, 조기경보 한계, 운전조건, 센서 간 관계, 원인 구분, 정비 효과
  02_baseline.py     기준 예제(데이터셋 toolkit의 연주 예제) 재현과 오류 분석
data/posko/          변환된 데이터 (커밋하지 않음)
figures/             번호_eda_내용.png (커밋하지 않음)
reports/             문제정의서·결과보고서·발표자료
```

## 분석 요약

**EDA 주요 결론** (학습 세트 216개 시나리오)
- 고장은 51건이다. **점진 고장 45건**은 열화가 14.5~54.5시간 이어진 뒤 고장 나고, **돌발 고장 6건**은 신호 없이 갑자기 고장 난다. 진단 정답의 `failed` 구간만 보면 6건만 보이므로, 고장 여부는 정비 기록의 `FAILURE_DT`로 판단한다.
- 열화 신호 4개: `MLD-LVL` 진폭, `CONTROL_DELAY`, `WD-LOD`(부하 보정)는 커지고 `OSC-STK`는 작아진다. **고장 24~36시간 전부터** 정상과 갈린다.
- 24시간 앞서 잡을 수 있는 고장의 상한은 약 76%(39/51건)다.
- 네 신호를 정상 분포로 표준화한 **평균 점수**는 정상 구간의 경계 초과 비율을 5%에서 0.4%로 줄이면서 고장 전 감지 비율 79%를 유지한다.
- 센서로 고장 원인(마찰·고착·제어 지연)은 구분할 수 없다. 그래서 **원인과 상관없이 24시간 안 고장 여부**를 예측한다.

**기준 예제 성능** (검증 세트, 최근 12시간 요약 + 랜덤포레스트)

| AP | 정밀도 | 재현율 |
|---|---|---|
| 0.806 | 0.789 | 0.800 |

- 임계값을 검증 세트에서 고르고 같은 세트로 평가해서 정밀도·재현율은 낙관적이다.
- 오경보 15개는 모두 고장 24~45시간 전의 "이른 경보"였다. 놓친 양성 14개 중 8개는 돌발 고장이다(점진 고장만 보면 재현율 0.903).
