# 연주 설비 조기경보 — EDA 정리

> 작성·갱신: 2026-10-13 · 데이터: POSKO 예측정비 합성 데이터 `pdm-v2.2.0` · 분석 범위: 학습 세트 216개 시나리오

## 한눈에 보기

- **주제**: 연주 설비(`P1-CC1-INS01`)가 **24시간 안에 고장 날지** 미리 알리는 조기경보
- **결론 요약**
  - 고장 24~36시간 전부터 센서 4개에 뚜렷한 신호가 나타난다. 조기경보는 충분히 가능하다.
  - 24시간 앞서 잡을 수 있는 고장은 약 **76%(39/51건)**이다. 나머지는 신호 없이 갑자기 고장 나거나 열화 기간이 짧다.
  - 센서로 **고장 원인은 구분할 수 없다.** 원인과 상관없이 고장 여부만 예측한다.
- **진행 상태**: 데이터 준비, EDA, 기준 예제 재현, 전처리·특징 함수 완료 → 다음은 ★ 논의 항목(6-1) 결정 후 조기경보 모델

## 1. 데이터 개요

### 1-1. 구조

- 72시간짜리 **독립된 상황(시나리오) 360개**로 이루어져 있다. 시나리오끼리는 이어지지 않는다.
- 시나리오 번호는 `S0001`~`S0360`이고, 시작 시각 순서로 분할돼 있다.

| 분할 | 시나리오 | 기간 | 정답 | 용도 |
|---|---|---|---|---|
| 학습 (train) | `S0001`~`S0216` (216개) | 2025-01 ~ 2027-05 | 있음 | EDA, 특징 설계, 모델 학습 |
| 검증 (validation) | `S0217`~`S0288` (72개) | 2027-05 ~ 2028-02 | 있음 | 모델 비교, 임계값 결정 |
| 테스트 (test) | `S0289`~`S0360` (72개) | 2028-02 ~ 2028-12 | **없음** | 최종 예측 |

- 설비는 7대(교반기 → 배풍기 1·2 → **연주** → 용접 → 소둔 → 조질압연)이고, 이 중 **연주**를 다룬다.
- 연주를 고른 이유: 고장 사례가 다른 설비보다 3배 이상 많다(원인 시나리오 학습 61개 vs 18개). 그래서 검증 결과를 믿을 수 있다.

### 1-2. 사용하는 파일

| 종류 | 파일 | 내용 | 크기 |
|---|---|---|---|
| 원자료 | `casting` | 연주 센서, 5초 간격 | 1,866만 행 (시나리오당 51,840행) |
| 정비 이력 | `maintenance`, `calendar` | 정비 기록, 정기수리 계획 | 수백 행 |
| 조업 이벤트 | `events` | 운전조건 변경 | 수천 행 |
| 정답 | `labels` | 6·24시간 고장 위험 (6시간마다) | 시나리오당 13개 시점 |
| 정답 | `diagnostics` | 상태 구간(정상·열화·고장·정비), 원인 | — |
| 정답 | `targets` | 잔여수명, 교체 정책 | 시나리오당 13개 시점 |

### 1-3. 지켜야 할 규칙

1. **분할 원칙**: EDA와 특징 설계는 **학습 세트로만** 한다. 검증 세트는 모델 비교·임계값 결정에만 쓰고, 검증 세트 그래프를 보고 특징을 고르지 않는다.
2. **정답 열**(`labels`, `diagnostics`, `targets`의 열)은 특징으로 쓰지 않는다.
3. **예측 시점 이후 정보**(센서·정비·검사)는 쓰지 않는다.
4. **검열된 정답**(결과를 알 수 없는 시점)은 0(고장 안 남)으로 채우지 않고 뺀다.

## 2. 컬럼 사전

### 2-1. 연주 원자료 (`casting`, 5초 간격)

| 컬럼 | 뜻 | 단위·값 |
|---|---|---|
| `SCENARIO_ID` | 시나리오 번호 | `S0001`~`S0360` |
| `MEAS_DT` | 관측 시각 | UTC |
| `EQP_CD` | 설비 ID | 연주 = `P1-CC1-INS01` |
| `SLAB_NO` | 슬래브 번호 (1시간에 1개) | — |
| `LOAD` | 정격 대비 부하 비율. 운전 조건이라 12~18시간 주기로 오르내린다 | 0.62~0.94 |
| `WD-SPD` | 인발 속도 (주편을 뽑아내는 속도). `LOAD`와 상관 1.0 | — |
| `WD-LOD` | 인발 부하 (뽑아낼 때 걸리는 힘) | — |
| `OSC-FRQ` | 몰드 진동 주파수. 운전 중 항상 2.0 | Hz |
| `OSC-STK` | 몰드 진동 스트로크 (진동 폭) | mm |
| `MLD-LVL` | 몰드 안 쇳물 높이. 약 22분 주기로 오르내린다 | mm |
| `CONTROL_DELAY` | 제어 지연 (명령 후 반응까지 걸린 시간) | 초 |
| `RUNNING` | 운전 상태 | 1 운전 / 0 정지 |
| `QUALITY_FLAG` | 측정 품질. **고장 라벨이 아니다** | `ok` / `missing` |

### 2-2. 정답·정비 기록

| 파일 | 컬럼 | 뜻 |
|---|---|---|
| `labels` | `OBSERVED_AT` | 예측 시점 (00·06·12·18시) |
| | `RISK_24H`, `RISK_6H` | **이후 정비를 더 안 한다면** 24·6시간 안에 고장 나는지 (1/0) |
| | `CENSORED_24H` | 1이면 결과를 알 수 없음 (관측 종료·정비 중) |
| `diagnostics` | `START_AT`, `END_AT` | 상태 구간의 시작·끝 |
| | `HEALTH_STATE` | `normal` 정상 / `degraded` 열화 / `failed` 고장 / `maintenance` 정비 |
| | `FAULT_MODE` | `friction` 진동 마찰 / `sticking` 밸브 고착 / `control-delay` 밸브 제어 지연 / `background-wear` 완만한 부수 열화 |
| | `CAUSE_PART` | `oscillator` 진동장치 / `valve` 밸브 |
| `targets` | `AT_RISK` | 지금 새 고장을 판단할 수 있는 상태인지 (1/0) |
| | `RUL_EVENT`, `RUL_HOURS` | 관측 기간 안에 고장 나는지, 고장까지 남은 시간 |
| `maintenance` | `MNT_TYPE` | `repair` 고장 후 복구(8시간) / `replace` 정기 교체(4시간) / `partial` 부분 정비(2시간) |
| | `FAILURE_DT` | 고장 시각. 값이 있으면 고장으로 시작된 정비 |
| `events` | `AFT_VAL` | 바뀐 운전조건 코드 (0·1·2) |

### 2-3. 분석에서 만든 컬럼 (1시간 요약 표)

**시간·구간**

| 컬럼 | 뜻 |
|---|---|
| `HOUR` | 시나리오 시작 후 몇 번째 시간 (0~71) |
| `SEG` | 운전 구간 번호. 정비로 멈췄다 다시 돌 때마다 1씩 늘어난다 |
| `SEG_HOUR` | 운전 구간 안에서 몇 번째 시간. 0~1은 기준 구간 |
| `N_RUN` | 그 1시간 중 운전한 행 수 (최대 720) |
| `COND` | 그 시간의 운전조건 코드 |

**신호 (센서 이름 뒤 꼬리표)**

| 컬럼 | 뜻 |
|---|---|
| `MLD-AMP` | `MLD-LVL`의 1시간 표준편차 = **몰드 레벨이 오르내리는 폭(진폭)** |
| `_ADJ` | 부하 영향을 뺀 값 |

**비교용 이름표 (특징으로 쓰지 않음)**

| 컬럼 | 뜻 |
|---|---|

| `OUT_신호명` | 그 신호가 정상 범위(정상 시나리오의 95% 경계)를 벗어났는지 |
| `N_OUT` | 신호 4개 중 몇 개가 벗어났는지 |

## 4. EDA 핵심 결과

### 4-1. 고장은 두 종류다

학습 세트 고장 51건(49개 시나리오).

| 종류 | 건수 | 특징 | 조기경보 |
|---|---|---|---|
| **점진 고장** | 45건 | 열화가 14.5~54.5시간(중앙값 36시간) 이어진 뒤 고장 | 가능 |
| **돌발 고장** | 6건 | 열화 없이 정상에서 바로 고장. 고장 전 신호 없음 | 불가능 |

> 주의: 진단 정답의 `failed` 구간만 세면 고장이 6건으로 보인다. 대부분 고장 즉시 복구가 시작돼 진단에는 "열화 → 정비"로만 나타나기 때문이다. **고장 여부는 정비 기록의 `FAILURE_DT`로 판단한다.**

### 4-2. 열화 신호 4개

고장 전 시간대별로 정상 시나리오와 얼마나 잘 갈리는지(AUC, 0.5 = 구분 못 함, 1 = 완전 구분).

| 신호 | 방향 | 고장 전 0~6시간 | 고장 전 24~36시간 |
|---|---|---|---|
| `MLD-LVL` **진폭** | 커짐 | 0.95~0.98 | 0.90~0.95 |
| `CONTROL_DELAY` | 커짐 | 0.94~0.99 | 0.91~0.93 |
| `OSC-STK` | 작아짐 | 0.93~0.95 | 0.80~0.86 |
| `WD-LOD` (부하 보정) | 커짐 | 0.91~0.98 | 0.76~0.89 |
| `MLD-LVL` 평균 | 변화 없음 | 약 0.5 | 약 0.5 |

- `MLD-LVL` 진폭이 **가장 먼저** 벗어난다(점진 고장 45건 중 44건). 감지 리드타임 중앙값 39시간.
- 센서가 벗어나는 시점은 진단상 열화 시작과 거의 같다. 센서가 열화를 바로 잡는다.

### 4-3. 네 신호를 합치면 오경보가 크게 준다

각 신호를 정상 분포 기준으로 표준화한 뒤, 정상 범위 경계를 넘는 비율.

| 점수 | 정상 구간 (오경보 쪽) | 고장 전 24~36시간 (감지 쪽) |
|---|---|---|
| 단일 신호 | 5.0% | 62~84% |
| **네 신호 평균** | **0.4%** | **79%** |
| 최댓값 | 18.2% | 86% |

정상일 때는 신호가 따로 흔들려 평균에서 상쇄되고, 고장 전에는 함께 올라 평균도 오른다.

### 4-4. 오경보와 이른 경보

- **정상 시나리오의 짧은 혹**: 신호 2개 이상이 동시에 벗어나는 일이 정상 155개 중 57개 시나리오에서 103번. 대부분 1~3시간, 최장 10시간. 고장 전 이상은 모두 12시간 이상 이어진다.
  - "6시간 이상 지속" 조건이면 정상 혹은 4/103개만 남고, 점진 고장 45건은 모두 잡힌다. 대신 경보가 6시간 늦어진다.
- **정답의 뜻**: `RISK_24H`는 "이후 정비를 더 안 한다면" 기준이다. 정기 교체로 고장을 막은 시나리오(11개)도 교체 전에는 고장 예정으로 표시된다. 다만 교체 시점에 고장까지 24시간 넘게 남은 경우가 많아, **신호는 강한데 `RISK_24H=0`인 "이른 경보" 시점**이 생긴다.

### 4-5. 그 밖의 결과

- **원인 구분 불가**: 네 신호의 반응 조합으로 원인을 맞히면 정확도 0.35~0.42로, 무작위 기준선 0.37과 같다. 원인과 부품은 1:1로 묶여 있다(마찰 = 진동장치, 고착·제어 지연 = 밸브).
- **정비 효과**: 어떤 정비도 신호를 처음 수준까지 되돌리지 않는다(회복률 0.7~0.9). 부분 정비 6건은 모두 0~4시간 만에 다시 열화돼 25~33시간 뒤 고장 났다.
- **운전조건**: 모든 시나리오가 같은 일정(12시간마다 0 → 1 → 2)이라 경과 시간과 같은 정보다. 센서 영향도 거의 없다.
- **시나리오마다 기준 수준이 다르다**: `OSC-STK`, `CONTROL_DELAY`는 시나리오 간 차이가 시나리오 안 변동보다 7~13배 크다. 절대값이 아니라 변화량을 봐야 한다.

## 5. 확정된 결정

### 규칙·범위
1. EDA·특징 설계는 학습 세트로만, 검증 세트는 모델 비교·임계값에만, 테스트는 최종 예측에만 쓴다.
2. 정답 열과 예측 시점 이후 정보는 특징으로 쓰지 않는다.
3. 검열된 정답은 학습·평가에서 뺀다.
4. 고장 여부는 정비 기록의 `FAILURE_DT`로 판단한다.
5. **주제: 원인과 상관없이 24시간 안 고장 여부 예측.** 원인 진단은 범위에서 뺀다.

### 전처리
6. 정지 구간(`RUNNING=0`)은 빼고, 정비 후 재가동하면 운전 구간을 새로 시작한다.
7. 1시간 단위로 요약한다. `MLD-LVL`은 평균 대신 1시간 표준편차(진폭)를 쓴다.
8. 부하 보정: `OSC-STK`, `CONTROL_DELAY`는 공통 기울기 차감, `WD-LOD`는 `(WD-LOD − 3.06) / LOAD`.
9. 운전조건에 따른 보정은 하지 않는다.

### 특징
10. 쓰는 센서: `MLD-LVL` 진폭, `CONTROL_DELAY`, `WD-LOD`(보정), `OSC-STK`.
    빼는 것: `OSC-FRQ`(상수), `WD-SPD`(`LOAD`와 같음), `MLD-LVL` 평균(신호 없음), 운전조건 코드(경과 시간과 같은 정보).
11. 기준을 두 가지로 잡는다: **재가동 후 변화량**(이번 구간에서 얼마나 빨리 나빠지나)과 **처음 수준 대비 변화량**(시나리오 시작부터 얼마나 나빠졌나).
12. 네 신호의 **표준화 평균 점수**를 핵심 특징으로 쓰고, `MLD-LVL` 진폭은 단독 특징으로도 쓴다.
13. 부하 기울기·절편과 표준화 기준은 학습 세트 정상 시나리오에서 한 번 정해 검증·테스트에 그대로 쓴다.

### 6-3. 논의 자료: 혼동행렬과 비용

**혼동행렬의 뜻 (우리 문제 기준)**

| | 실제로 24시간 안 고장 (1) | 24시간 안 고장 없음 (0) |
|---|---|---|
| **경보 냄** | **TP** 맞은 경보 | **FP** 오경보 |
| **경보 안 냄** | **FN** 놓친 고장 | **TN** 맞게 조용함 |

- 정밀도 = TP / (TP + FP): 경보를 냈을 때 실제로 고장 난 비율. 낮으면 현장이 경보를 믿지 않는다.
- 재현율 = TP / (TP + FN): 실제 고장 중 미리 잡은 비율. 낮으면 고장을 놓친다.

**기준 예제의 혼동행렬 (검증 세트 639개 예측 시점)**

| | 실제 1 (70개) | 실제 0 (569개) |
|---|---|---|
| 경보 냄 (71개) | TP **56** | FP **15** |
| 경보 안 냄 (568개) | FN **14** | TN **554** |

- 정밀도 0.789, 재현율 0.800
- **FP 15개는 모두 고장 24~45시간 전의 "이른 경보"**다. 고장 예정이 없는데 울린 진짜 오경보는 0개다 → A의 근거
- **FN 14개 중 8개는 돌발 고장**이다. 점진 고장만 보면 재현율 0.903 → B의 근거

**비용 규칙 (데이터셋 `toolkit/targets.md`, 단위는 점수)**

| 항목 | 점수 |
|---|---|
| 부품 교체 | 12 |
| 고장 후 복구 | 30 |
| 정지 시간 | 1시간당 2 (교체 4시간, 복구 8시간) |
| 고장 벌점 | 20 |
| 불필요한 정비 벌점 (아직 멀쩡한 부품 교체) | 8 |

**혼동행렬 칸별 비용 (경보가 나면 바로 교체한다고 가정)**

| 결과 | 일어나는 일 | 비용 |
|---|---|---|
| TP 맞은 경보 | 고장 전에 교체 | 12 + 4h×2 = **20** |
| FN 놓친 고장 | 고장 → 복구 | 30 + 8h×2 + 20 = **66** |
| FP 진짜 오경보 | 멀쩡한 부품 교체 | 12 + 4h×2 + 8 = **28** |
| FP 중 이른 경보 | 열화 중인 부품을 일찍 교체 | 약 **20** |
| TN | 아무 일 없음 | 0 |

- 고장 하나를 미리 잡으면 46점(66 − 20)을 아끼고, 진짜 오경보는 한 번에 28점이 든다. **놓친 고장이 오경보보다 훨씬 비싸서** 재현율을 조금 더 중시하는 임계값에 근거가 있다 → D의 근거
- 비용은 예측 시점이 아니라 **고장 단위**로 세야 한다. 고장 하나 앞에 예측 시점이 여러 개라, 시나리오마다 "첫 경보에서 교체 → 그 뒤 고장은 막힘"을 시간 순서로 따라가며 계산한다.
- **부품 선택 가정이 결과를 크게 바꾼다.** 센서로 원인 부품(진동장치 vs 밸브)을 구분할 수 없어서(EDA 10절), 경보가 나도 틀린 부품을 바꾸면 고장을 못 막는다 → C의 근거
- `targets`에 "정답을 아는 최적 정책의 비용"(`POLICY_SCORE`)과 "기다렸을 때의 비용"(`WAIT_SCORE`)이 있어, 우리 모델의 비용을 "아무것도 안 함 / 기준 예제 / 우리 모델 / 최적 정책"과 나란히 비교할 수 있다.

## 7. 주의할 한계

- EDA의 AUC와 경계 초과 비율은 **신호의 세기**를 보여 줄 뿐, 모델 성능이 아니다. 비교군이 정상 시나리오뿐이고 같은 시나리오의 시간끼리 독립이 아니다. 실제 모델 성능은 이보다 낮을 것이다.
- 정기 교체 후 다시 열화되는 구간(정답 0 또는 검열)에서 신호가 벗어나 오경보가 나는지는 아직 확인하지 않았다.
- **합성 데이터**다. 결과는 실제 설비 특성이 아니라 이 데이터의 생성 규칙을 반영한다.
