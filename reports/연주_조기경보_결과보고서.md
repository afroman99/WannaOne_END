## 0. 요약

- **문제**: 연주 설비가 24시간 안에 고장 날지 미리 알려, 비싼 고장 후 복구(66점, 정지 8시간) 대신 교체(20점, 정지 4시간)로 막는다.
- **결과**: 검증 세트에서 신호가 있는 **점진 고장 14건을 모두** 고장 4시간 전까지 감지했고, 첫 경보는 고장 **중앙값 24.4시간 전**에 났다. 순위 능력(AP 0.860)과 리드타임이 비교한 세 모델 중 가장 좋다. 다만 정해 둔 경보 기준에서 정밀도·F1·비용은 Z-score 기준 모델과 기준 예제보다 조금 낮다(4절).
- **성공 기준**: 문제정의서의 S1~S5 중 **4개를 달성**했다. S3(진짜 오경보 0)은 1번이 나와 달성하지 못했다. 그 1번은 열화가 시작되기 45분 전에 울린 경보로, 고장이 관측 기간 뒤라 정답상 오경보로 셌다.
- **개정**: 외부 검토를 받아 고치는 과정에서, 이전 모델이 "오래 돌았으면 고장"이라는 착시를 배운 것을 찾아 없앴다. 그래서 최종 모델이 로지스틱 회귀에서 **랜덤포레스트**로, 경보 기준이 0.76에서 **0.67**로 바뀌었다(2-2절).
- **한계**: 신호 없이 갑자기 고장 나는 돌발 고장(검증 2건)은 잡을 수 없다. 센서로는 5초 원자료까지 봐도 원인 부품을 알 수 없어, 비용 효과는 부품을 얼마나 맞힐 수 있느냐에 달려 있다. 정비 기록의 단서("직전이 부분 정비면 그 부품")는 현장과 맞지 않는 합성 데이터의 성질이었다(6-1절).
- **현장 관점**: 현장에서는 부품 조달 때문에 24시간도 빠듯하다. 데이터상 신호는 길어야 고장 36시간 전에 나타나서 경보를 더 앞당기는 데는 한계가 있다. 그래서 **두 부품의 예비품 확보 + 2단계 경보(주의·경보)**를 함께 제안한다(7절).
- **주의 단계**: "지금 열화 중인가"를 맞히는 모델을 따로 두었다. 현장에서는 주의를 받으면 점검하고 다음 정비 때 함께 정비하므로 헛걸음 비용이 작다. 그래서 주의 중 85% 이상이 실제 열화인 기준(0.38)을 학습 세트 교차검증으로 정했다. 검증 세트에서 점진 고장 14건 모두에 주의가 켜졌고, 경보보다 평균 12.4시간 먼저였다. 다만 주의 정밀도는 0.774로 목표 0.85에 못 미쳤다(7-5절).

## 1. 문제와 목표

| 항목 | 내용 |
|---|---|
| 대상 | 연주 설비 `P1-CC1-INS01` (진동장치, 밸브) |
| 질문 | 지금 시점에서 연주 설비가 **24시간 안에 고장 나는가** (원인 무관, 부록 A E9) |
| 예측 시점 | 시나리오 시작 후 0, 6, 12, …, 66시간. 그 시각에 정비 중이면 뺀다 |
| 정답 | 24시간 안 고장이면 1. 고장이 24시간 넘게 남았거나, 24시간 넘게 고장이 없음이 확인되면 0. 관측이 끝나 알 수 없으면 뺀다 |
| 쓰는 정보 | 예측 시점까지 **끝난** 1시간 구간의 센서, 예측 시점까지 **끝난** 정비 기록 |
| 문제 유형 | 지도학습 이진 분류. 출력은 24시간 안 고장 확률, 확률이 임계값 이상이면 경보 |
| 왜 24시간인가 | 교체에 4시간이 걸리고, 인력·부품·생산 일정을 준비하려면 하루 전에 아는 것이 바람직하다 |

- 정답 규칙은 데이터셋의 기준 예제와 같게 맞췄다. 그래서 같은 시점에서 기준 예제와 비교할 수 있다.
- 시점 수: 학습 1,919개(양성 217개, 11%), 검증 639개(양성 70개, 11%). 정답을 알 수 없어 평가에서 빠지는 시점은 학습 589개, 검증 198개다(대부분 관측 끝 48시간 이후).
- 자세한 배경과 범위는 문제정의서를 본다.

## 2. 데이터와 방법

**데이터와 시간 기준 분할**

72시간짜리 **독립된 상황(시나리오) 360개**다. 시나리오끼리는 이어지지 않는다. 시나리오 번호 순서가 시작 시각 순서와 같고, 그 순서로 나뉘어 있다.

| 분할 | 시나리오 | 기간 | 정답 | 용도 |
|---|---|---|---|---|
| 학습 | `S0001`~`S0216` (216개) | 2025-01 ~ 2027-05 | 있음 | EDA, 특징 설계, 모델·임계값 선택(교차검증) |
| 검증 | `S0217`~`S0288` (72개) | 2027-05 ~ 2028-02 | 있음 | 최종 평가 (한 번만) |
| 테스트 | `S0289`~`S0360` (72개) | 2028-02 ~ 2028-12 | **없음** | 최종 예측 |

- **앞 구간으로 학습하고 뒤 구간으로 검증했고, 무작위로 섞지 않았다.**
- 설비 7대(교반기 → 배풍기 1·2 → **연주** → 용접 → 소둔 → 조질압연) 중 연주를 다룬다. 고장 원인이 있는 시나리오가 학습 세트에 61개로, 다음으로 많은 설비(18개)의 3배가 넘는다. 고장 사례가 적으면 검증 세트 결과가 몇 건에 좌우돼 믿기 어렵다.

**규칙**
- 탐색·특징 설계·모델 선택은 학습 세트로만 했다. 검증 세트는 마지막에 한 번만 평가했다.
- 학습 세트 안에서는 시나리오 단위 5겹 교차검증을 썼다. 같은 시나리오의 시점은 한 겹에만 들어간다. 보정값(부하 기울기·절편, 표준화 기준, 기준이 되는 정상 시나리오 선택)도 폴드마다 학습 부분으로만 다시 정했다.
- 정답 열(진단·잔여수명 등)은 특징으로 쓰지 않았다. 미래 정보가 섞이지 않았는지 원자료를 예측 시점에서 잘라 다시 계산해 확인했다(2,558개 시점 모두 일치, 부록 B-2).
- **원칙: 평가는 결과를 부풀리지 않게, 경보는 미탐(놓친 고장)을 줄이는 쪽으로.** 비용 규칙상 고장을 놓치면 66점, 오경보는 28~48점이라 놓치는 쪽이 더 비싸다.

**방법**

| 단계 | 내용 |
|---|---|
| 전처리 | 5초 값을 1시간으로 요약, 부하 영향 제거, 상황마다 다른 기준 수준을 없애려고 변화량으로 변환 (부록 A E3·E5) |
| 특징 (28개) | 열화 신호 4개의 크기·이동평균·변화율, 네 신호의 표준화 평균 점수, 이상 지속 시간, 정비 이력. 시간을 세는 특징은 뺐다 (부록 B-1) |
| 기준 모델 | **Z-score 기준 모델**: 네 신호를 정상 분포로 표준화한 점수(Z-score)의 평균을 학습 없이 그대로 위험도로 쓴다. 경보 기준은 같은 규칙으로 정한다 |
| 모델 | 3개 모델(로지스틱 회귀, 랜덤포레스트, 그래디언트 부스팅) × 2개 특징 묶음을 학습 세트 교차검증으로 비교 → **랜덤포레스트** 선택 (부록 B-5) |
| 경보 기준 | 학습 세트 교차검증에서 점진 고장을 모두 잡고 진짜 오경보가 0인 확률 기준 중 가장 낮은 값 (**0.67**, 부록 B-4 D) |
| 비교 대상 | 데이터셋이 제공하는 기준 예제 (최근 12시간 요약 + 랜덤포레스트), 같은 규칙으로 다시 평가 |
| 지표 | 혼동행렬, 정밀도, 재현율, F1, AP, 고장 단위 감지·리드타임, 비용. 정확도는 쓰지 않는다 (부록 B-3) |

### 2-1. 팀 결정 (모두 확정)

모델을 만들고 평가하면서 정해야 했던 갈림길 7개를 팀 논의로 정했다. 결정마다 선택지와 숫자 근거는 부록 B-4에 있다. A~D는 숫자를 **어떻게 셀지**(평가), E~G는 모델에 **무엇을 넣을지**(모델)에 대한 결정이다.

| # | 정한 것 | 결정 | 한 줄 근거 |
|---|---|---|---|
| A | 고장 24시간보다 일찍 울린 경보 | 오경보로 세고, 따로 보고 | 정답 정의를 바꾸지 않는다. 검증 세트 오경보 18개 중 17개가 실제 열화 중이었음을 함께 적는다 |
| B | 신호 없는 돌발 고장 | 대표 재현율에서 빼고, 따로 보고 | 어떤 모델로도 잡을 수 없다(신호 지속 0~1시간) |
| C | 경보가 나면 바꿀 부품 | 두 부품 모두 | 원인 부품을 알 수 없고, 밸브만 바꾸면 944~968점으로 더 비싸다(두 부품 860점) |
| D | 경보 기준 확률 | 규칙: 놓치는 고장 0, 진짜 오경보 0 중 가장 일찍 → **0.67** | 규칙은 그대로, 모델이 바뀌어 값이 0.76에서 0.67로 바뀌었다(2-2절) |
| E | 시간을 세는 특징 (경과 시간, 재가동 후 시간) | 특징으로 안 씀 | 관측 창이 만든 착시를 배워 관측 끝에 멀쩡한 설비에도 경보를 울렸다 |
| F | 정비 이력 | 특징으로 씀 | 정비 뒤에도 열화가 남고, 세 모델 모두 AP가 오른다 |
| G | "이상이 이어져야 경보" 조건 | 안 건다 | 줄일 오경보가 없고, 걸면 고장 4건을 놓치고 5시간 늦어진다 |

### 2-2. 개정: 외부 검토로 바뀐 것

다른 도구(Codex)로 코드 검토를 받아 4가지를 고쳤고, 그 과정에서 더 큰 문제 하나를 찾았다.

| # | 문제 | 고친 결과 |
|---|---|---|
| 1 | 정답을 알 수 없는 시점(관측 끝)의 경보가 비용에서 빠졌다 | 미확정 경보를 따로 세어 운영 비용에 범위로 더한다(6절) |
| 2 | 교차검증의 보정값 계산에 평가 폴드가 섞였다 | 폴드마다 학습 부분만으로 다시 정한다. 결과에는 거의 영향 없음 |
| 3·4 | 대시보드가 정비 전 신호와 미래의 정비 종료 시각을 보여 줬다 | 지금까지 알 수 있는 정보만 보여 준다 |
| **5** | **이전 모델이 "오래 돌았으면 고장"이라는 착시를 배웠다** | 착시를 만드는 특징 `SEG_HOURS`(재가동 후 지난 시간)를 뺐다. 최종 모델과 경보 기준이 바뀌었다 |

**5번은 무엇이었나**
- 학습 데이터에서 관측 끝(54시간 이후) 시점은 정답이 모두 "고장"이다. 결과를 확인할 시간이 모자라 "고장 안 남"인 시점이 빠지기 때문이다.
- 이전 모델은 이걸 이용해 관측 끝부분에서 **신호가 정상인 설비에도 경보**를 울렸다(학습 세트에서 정상 시점 22개). 정답이 있는 시점만 보는 평가로는 보이지 않았다.
- 고친 뒤 최종 모델은 정답을 알 수 없는 구간에서 울린 경보가 **모두 실제로 열화 중인 설비**였다.
- 대신 이전 모델의 좋아 보이던 숫자(AP 0.867, 재현율 0.952, 진짜 오경보 0)는 일부가 착시 덕분이어서, 고친 뒤 숫자가 조금 낮아졌다. 자세한 숫자는 부록 B-4 E.

**왜 경보 기준이 0.76에서 0.67로 바뀌었나 (쉬운 설명)**

> 1. 경보 기준은 **"몇 점 이상이면 경보"** 하는 선이다. 모델이 설비마다 0~1 사이 점수(고장 확률)를 매기고, 점수가 선을 넘으면 경보가 울린다.
> 2. **선을 긋는 규칙은 그대로다.** "고장은 하나도 놓치지 말고, 멀쩡한 설비에는 울리지 말고, 그 안에서 가장 일찍."
> 3. **바뀐 건 점수를 매기는 모델이다.** 이전 모델은 문제를 이해하지 않고 "오래 돌았으면 고장"이라는 요령을 외운 학생 같았다. 시험지(학습 데이터)에서 관측 끝부분 문제의 답이 모두 "고장"이었기 때문이다. 그 요령을 지우고 다시 공부시켰더니 점수를 매기는 방식이 달라졌다.
> 4. **점수 매기는 방식이 바뀌면 선도 다시 그어야 한다.** 체온계를 새것으로 바꾸면 "몇 도부터 열"이라는 기준을 새 체온계로 다시 확인하는 것과 같다.
> 5. **새 모델로 같은 규칙을 적용했더니 그 자리가 0.67이었다.** 0.66으로 내리면 멀쩡한 설비에 1번 울리고, 0.76을 그대로 쓰면 결과는 같은데 경보가 반 시간 늦어진다.

### 2-3. 시간 순서 교차검증으로 확인 (`04_model.py` 2-1절)

학습 세트 안의 5겹 교차검증은 시나리오를 섞지 않고 나누지만, 시간 순서를 지키지는 않는다. 그래서 시나리오를 시간 순서로 6묶음으로 나누고, **앞 묶음들로 학습해 바로 다음 묶음을 평가**하는 방식으로 다시 돌렸다(첫 묶음 36개는 학습에만 쓰임, 평가 180개).

| 모델 · 특징 | 5겹 교차검증 AP (선택에 사용) | 시간 순서 교차검증 AP | 시간 순서에서의 임계값 |
|---|---|---|---|
| 로지스틱 회귀 · 센서 + 정비 이력 | 0.830 | **0.829** | 0.88 |
| **랜덤포레스트 · 센서 + 정비 이력 (선택)** | **0.837** | 0.823 | 0.74 |
| 로지스틱 회귀 · 센서 | 0.823 | 0.824 | 0.73 |
| 랜덤포레스트 · 센서 | 0.834 | 0.815 | 0.74 |
| 그래디언트 부스팅 (두 특징 묶음) | 0.823 / 0.828 | 0.791 / 0.792 | 0.78 / 0.69 |

- **바뀌는 것**: 시간 순서로 보면 1위가 로지스틱 회귀(0.829)이고 선택한 랜덤포레스트(0.823)와 0.006 차이다. 같은 규칙으로 정한 랜덤포레스트의 임계값은 0.74로, 지금의 0.67보다 높다.
- **바뀌지 않는 것**: 여섯 조합 모두 점진 고장을 전부 잡고(36/36), 1·2위 차이가 0.01 안쪽이라 "모델보다 특징이 성능을 정한다"는 결론은 같다.
- **어떻게 했나**: 선택은 처음 정한 5겹 교차검증 결과(랜덤포레스트, 0.67)를 그대로 썼다. 검증 세트 결과를 이미 본 뒤라, 지금 선택 방식을 바꾸면 결과를 보고 고르는 셈이 되기 때문이다. 대신 이 차이를 한계로 적는다(9절). 임계값이 0.67~0.74 사이에서 흔들릴 수 있다는 뜻이다.

### 4-1. 어디서 나아졌나: Z-score 기준 모델 → 우리 모델 (+ 기준 예제)

먼저 **학습 없이 Z-score만 쓴 기준 모델**을 만들고, 그다음 지도학습 모델로 갔다. 기준 예제도 지도학습 모델이라 함께 비교했다.

| 단계 | 방법 | 학습 여부 | AP: 학습 세트 (교차검증) | AP: 검증 세트 |
|---|---|---|---|---|
| ① 기준 예제 | 원래 센서값의 최근 12시간 요약 + 랜덤포레스트 | 지도학습 | 0.813 | 0.806 |
| ② Z-score 기준 모델 | 네 신호를 정상 분포로 표준화한 Z-score의 평균(`SCORE_F`, 처음 수준 대비)을 그대로 위험도로 사용 | **학습 없음** | 0.838 | 0.830 |
| ③ 우리 모델 | 특징 28개 + 랜덤포레스트 | 지도학습 | 0.837 | **0.860** |

- **① → ②**: 정답을 보고 학습하지 않은 점수 하나가 기준 예제의 지도학습 모델보다 낫다. EDA에서 만든 전처리(부하 보정, 상황별 기준을 없앤 변화량, 정상 분포 기준 표준화, 네 신호 평균)가 **개선의 대부분**을 만들었다.
- **② → ③**: 학습 세트에서는 차이가 없고(0.838 vs 0.837), 검증 세트에서 0.030 올랐다. 추세·지속 시간·정비 이력을 더한 지도학습의 몫은 작다.
- 그래서 **좋은 알고리즘보다 데이터를 이해하고 특징을 잘 만든 것이 성능을 결정했다.** 6개 모델·특징 조합의 교차검증 AP 차이도 0.823~0.837로 작았다(부록 B-5).

**참고로 볼 숫자**
- ②의 점수는 학습 세트 정상 시나리오의 분포로 표준화만 했고, 정답으로 학습한 것은 없다. 교차검증에서는 표준화 기준도 폴드마다 학습 부분으로 다시 정했다. 시작 직후·정비 직후처럼 점수가 비어 있는 시점은 가장 낮은 위험으로 두고 계산했다.
- ②의 경보 기준(점수 5.48)은 우리 모델과 같은 규칙(학습 세트 교차검증에서 점진 고장을 모두 잡고 진짜 오경보 0인 값 중 가장 낮은 값)으로 정했다.
- ②의 검증 세트 AP는 특징을 만들던 단계에서 한 번 확인한 적이 있다. 그 숫자로 모델·특징·임계값을 고르지는 않았지만(모두 학습 세트 교차검증으로 결정), "검증 세트는 마지막에 한 번만"이라는 원칙에 맞추어 이 표는 **설명을 위한 참고 비교**로 본다.

### 6-1. 원인 부품을 가려낼 수 있나 (`07_cause_part.py`)

EDA(부록 A E9)에서는 1시간 요약 신호로 원인 부품을 구분할 수 없었다. 두 가지 정보를 더 확인했다.

**① 5초 원자료의 파형: 구분되지 않는다**
- 열화 구간 162개(학습 119, 검증 43)마다, 구간 끝 6시간의 5초 원자료에서 파형 특징 182개를 만들었다. 신호 다섯 개(인발 부하, 진동 스트로크, 몰드 레벨, 제어 지연, 부하)마다 흔들림 크기, 빠른 변화, 비대칭, 주파수 대역별 세기, 자기상관을 계산했다. 신호끼리의 상관과 결측 비율도 넣었고, 시나리오 처음 정상 6시간 대비 변화도 함께 봤다.
- 이 특징으로 부품을 맞히는 랜덤포레스트를 학습 세트 교차검증(시나리오 단위 5겹)으로 평가했다.

| 무엇을 맞히나 | 열화 구간 | 교차검증 AUC |
|---|---|---|
| 부품: 전체 열화 구간 | 119개 | 0.64 |
| **부품: 고장으로 이어지는 모드만 (마찰 = 진동장치 vs 고착·제어 지연 = 밸브)** | 83개 | **0.40** |
| 부품: 배경 마모 안에서만 | 36개 | 0.34 |
| 참고: 배경 마모인지 아닌지 (심각도) | 119개 | 0.97 |

(AUC 0.5 = 찍기. 0.5보다 낮은 것도 "구분 못 함"이다.)

- **전체에서 0.64가 나온 것은 부품이 아니라 심각도를 맞힌 것이다.** 배경 마모는 가벼운 열화로 고장으로 이어지지 않는다. 그런데 진동장치 쪽에 많고(26 vs 10), 파형으로 쉽게 구분된다(AUC 0.97). 그래서 "가벼우면 진동장치"로 맞힌 것처럼 보였다.
- **같은 모드끼리 놓고 보면 찍기 수준이다.** 경보에서 실제로 필요한 건 고장으로 이어지는 모드의 구분인데, 여기서 AUC 0.40이었다. 검증 세트에서도 0.57이었다.
- **라벨 섞기 검사**: 특징 하나만 볼 때 가장 좋은 것은 AUC 0.74였다. 하지만 부품 라벨을 무작위로 섞어도 특징 182개 중 가장 좋은 것은 보통 0.69, 상위 5%에서 0.74가 나왔다. 특징이 많으면 우연히 좋아 보이는 것이 하나쯤 생긴다.
- 그림 `18_part_5초파형_부품구분.png`: 왼쪽은 무엇을 맞히느냐별 AUC, 오른쪽은 실제 라벨(빨간 선)이 섞은 라벨의 분포(회색) 안에 들어 있다는 그림이다.
- **결론: 이 데이터에서는 센서가 원인 부품과 상관없이 같은 모양으로 반응한다.** 1시간 요약이든 5초 원자료든 구분할 정보가 없다. 합성 데이터의 생성 규칙이 그렇게 만들어졌을 가능성이 크다. 실제 설비라면 진동장치와 밸브의 파형이 다를 수 있어 다시 확인할 가치가 있다.

**② 정비 기록: 직전 정비가 부분 정비면 그 부품이다**

점진 고장마다 그 전에 끝난 마지막 정비를 봤다.

| 직전 정비 | 학습 세트 (진동장치 / 밸브 고장) | 검증 세트 |
|---|---|---|
| 진동장치 부분 정비 | **2 / 0** | **1 / 0** |
| 밸브 부분 정비 | **0 / 4** | **0 / 1** |
| 밸브 정기 교체 | 0 / 1 | — |
| 없음 | 13 / 25 | 5 / 7 |

- **직전이 부분 정비였던 고장은 학습 6건, 검증 2건 모두 그 부품의 고장이었다.**
- 거꾸로 봐도 같다. 학습·검증 세트의 부분 정비 8번은 **모두** 24~33시간 뒤 같은 부품의 고장으로 이어졌다. 이 데이터에서 부분 정비는 고장을 하루쯤 미룰 뿐이다.
- 다만 이 경우는 고장의 일부다(학습 45건 중 6건, 검증 14건 중 2건). 대부분은 직전 정비가 없어 정보가 없다.
- 정비 기록은 예측 시점 전에 끝난 것만 쓰므로, 경보가 난 시점에 현장에서 알 수 있는 정보다.

**③ 참고: 이 규칙을 쓰면 검증 세트 비용 860 → 820 (④ 때문에 채택하지 않음)**

| 전략 (검증 세트, 평가 가능 구간) | 비용 |
|---|---|
| 두 부품 모두 교체 (지금, 결정 C) | 860 |
| 직전이 부분 정비면 그 부품만, 아니면 두 부품 교체 | 820 (−40) |

- 고장 전 경보 2건(S0233 진동장치, S0281 밸브)에서 한 부품만 바꿔 각각 20점씩 줄었다. 두 건 모두 부품이 맞았다.
- 고장과 무관한 경보 중에는 직전이 부분 정비인 경우가 없었다.

**④ 현장 관점: 이 규칙은 현장에서는 성립하지 않는다 → 결정 C는 그대로**

팀원의 현장 경험으로는 **부분 정비가 제대로 수행되면 같은 부품이 다시 말썽인 경우는 드물다.** 다시 말썽인 경우는 딱 두 가지다.
1. 정비를 제대로 수행하지 않았을 때
2. 부품 자체가 불량일 때

- 이 데이터에서는 부분 정비 8번이 모두 같은 부품의 고장으로 이어졌다. 현장의 "드물다"와 정반대다. 그러니 이 규칙은 **합성 데이터의 생성 규칙**(부분 정비 = 고장을 잠시 미루는 조치)에서 나온 것이다. 현장의 정비 효과를 나타낸다고 볼 수 없다.
- 이 규칙을 비용 계산에 넣으면 데이터에만 맞춘 결과가 된다. 검증 세트의 860 → 820도 그렇게 읽어야 한다. **그래서 결정 C(두 부품 모두 교체)는 바꾸지 않는다.**
- **현장에서 쓸 수 있는 건 반대 방향이다.** 정비한 부품이 곧바로 다시 열화한다면, 그 자체가 **정비 불량이나 부품 불량의 신호**다. 이때는 그 부품을 먼저 의심하고, 정비 작업 내용과 부품 로트를 확인한다. 이건 비용을 줄이는 규칙이 아니라 점검 순서에 대한 안내다. 주의 단계(7-5절)의 장비 점검에 함께 넣을 수 있다.

## 7. 현장 관점: 리드타임과 부품 조달

### 7-1. 현장의 요구

팀원의 현장 경험으로는 **24시간도 빠듯하다.** 정비 인력은 맞출 수 있지만, **필요한 부품이 재고에 없을 수 있어** 조달 시간이 더 필요하다.

### 7-2. 데이터로 본 한계: 경보를 더 앞당길 수 있는가

고장 몇 시간 전부터 센서에 신호가 나타나는지 학습 세트 고장 51건으로 확인했다.

| 몇 시간 앞서 | 센서로 감지 가능한 고장 | 그 시점에 이미 열화가 시작된 고장 |
|---|---|---|
| 24시간 | 39건 (76%) | 40건 |
| 30시간 | 32건 (63%) | 31건 |
| 36시간 | 24건 (47%) | 24건 |
| 48시간 | 8건 (16%) | 6건 |

- 이 데이터에서 열화는 대부분 **고장 15~55시간 전(중앙값 36시간)**에 시작된다. 48시간 전에는 대부분의 설비가 아직 멀쩡해서 **어떤 모델로도 잡을 신호가 없다.**
- 예측 기간을 늘리면 정답을 만들 수 있는 시점도 줄어든다(관측이 72시간뿐이라). 학습 시점이 24시간 기준 1,919개에서 48시간 기준 1,245개로 줄어든다.
- 확률 기준을 낮춰 더 일찍 울리게 해도 얻는 시간이 작다. 학습 세트 교차검증에서 기준을 0.67에서 0.50으로 낮추면 리드타임 중앙값이 약 3.5시간(23 → 26.5시간) 늘지만, 멀쩡한 설비에 울리는 경보가 3번 생긴다(그림 `14_model_임계값별_경보결과.png`).

**결론: 예측만으로 확보할 수 있는 준비 시간은 길어야 하루~하루 반이다.** 이보다 긴 조달 기간은 예측이 아니라 재고로 해결해야 한다.

### 7-3. 지금 모델이 실제로 주는 준비 시간

검증 세트 점진 고장 14건의 첫 경보 시점(고장까지 남은 시간):

| 첫 경보 | 고장 수 |
|---|---|
| 36시간 이상 전 | 4건 |
| 30~36시간 전 | 1건 |
| 24~30시간 전 | 3건 |
| 24시간보다 늦게 (13.75~21.75시간 전) | 6건 |

- 14건 중 8건은 24시간보다 일찍 경보가 났다(가장 이른 것은 45시간 전). 평가에서 "이른 경보"로 따로 센 시점이 바로 이것이다.
- 현장 관점에서 이른 경보는 오경보가 아니라 **준비를 시작하라는 신호**로 쓸모가 있다. 검증 세트의 이른 경보 17개는 모두 실제로 열화 중인 설비였다.

### 7-4. 제안

**① 두 부품의 예비품을 늘 확보한다**
- 센서로는 원인 부품을 알 수 없으므로(6-1절), 경보가 나면 두 부품 모두 바로 쓸 수 있어야 한다.
- 정비 기록으로 본 부품별 교체 빈도 (학습 세트 216개 상황):

| 부품 | 고장 후 복구 | 정기 교체 | 부분 정비 | 교체가 있었던 상황 |
|---|---|---|---|---|
| 밸브 | 33 | 13 | 4 | 44개 |
| 진동장치 | 18 | 5 | 2 | 22개 |

- **밸브가 진동장치보다 약 2배 자주 바뀐다.** 한 상황(72시간) 안에서 같은 부품을 두 번 바꾼 경우도 있다(부분 정비 뒤 재고장 등). 예비품은 밸브를 더 넉넉히 둔다.

**② 경보를 두 단계로 나눠 조달과 연결한다**

| 단계 | 시점 | 할 일 |
|---|---|---|
| **주의** | 열화 시작 감지: 열화 감지 모델 확률 ≥ 0.38 (검증 세트에서 고장 중앙값 35시간 전, 경보보다 평균 12.4시간 먼저. 7-5절) | 장비 상태 확인, 설비가 돌면 다음 정비 때 함께 정비. 두 부품 재고 확인, 부족하면 바로 발주 |
| **경보** | 24시간 안 고장 위험 (지금의 경보 기준) | 교체 실행 |

- 재고가 있으면 주의 단계에서 확인만 하고, 없으면 경보보다 하루 이상 일찍 발주를 시작한다.
- 여러 설비의 주의·경보 상태를 모으면 앞으로 하루이틀 동안 필요한 부품 수를 미리 알 수 있다(대시보드 전체 현황 화면).

**③ 조달 기간이 하루 반보다 길면 재고 정책이 필수다**
- 예측으로 얻는 준비 시간은 데이터의 열화 기간을 넘을 수 없다(7-2).

### 7-5. 주의 단계의 기준 (학습 세트 교차검증, `06_caution.py`)

**정한 것**: 주의가 켜지는 기준. 경보 기준(0.67)은 그대로 두고, **주의 기준을 넘거나 경보가 나면 주의 단계**로 본다.

**① 주의의 정답은 "지금 열화 중인가"다**
- 주의는 "부품을 준비하라"는 신호다. 그래서 묻는 질문이 "24시간 안에 고장 나나"가 아니라 **"열화가 시작됐나"**다.
- 진단 정답의 열화(`degraded`) 구간을 주의의 정답으로 쓴다. 학습 세트 예측 시점 1,919개 중 319개(16.6%)가 열화 중이다.
- 진단 정답은 학습할 때 정답으로만 쓰고, 특징으로는 쓰지 않는다. 예측할 때는 경보 모델처럼 센서와 정비 기록만 본다.

**② 방법: 경보 모델의 기준을 낮추는 것보다, 열화 감지 모델을 따로 두는 게 낫다**

두 방법을 같은 규칙(아래 ③)으로 학습 세트 교차검증에서 비교했다. 점진 고장 45건 기준이다.

| | A: 경보 모델의 기준만 낮춤 | **B: 열화 감지 모델을 따로 둠** |
|---|---|---|
| 주의 기준 | 0.34 | **0.38** |
| 열화 아닌 설비에 켜진 주의 | 11번 / 76번 | 11번 / 78번 |
| 첫 주의: 고장까지 남은 시간 (중앙값) | 28.75시간 | **35.25시간** |
| 경보보다 먼저 켜진 시간 (평균 / 중앙값) | 5.9 / 6시간 | **13.5 / 12시간** |
| 경보보다 12시간 이상 먼저 켜진 고장 | 9건 | **35건** |

- 헛걸음 횟수가 같을 때 B가 경보보다 두 배 이상 먼저 켜진다.
- **왜 그런가**: 경보 모델은 "24시간 안에 고장 나는가"를 배웠다. 그래서 열화 초기(고장 30~50시간 전)를 "아직 아님"이라고 배웠고, 기준을 낮춰도 열화 초기를 잘 골라내지 못한다. 열화 감지 모델은 처음부터 열화 시작을 배우므로 거기서 바로 올라간다(교차검증 AP 0.977).
- 열화 감지 모델은 경보 모델과 같은 방식으로 골랐다(모델 3종 × 특징 묶음 2개 중 교차검증 AP 최대 → 랜덤포레스트 · 센서 특징). 여섯 조합의 AP가 0.969~0.977로 모두 비슷하다.
- 예측 시점이 6시간 간격이라 "먼저 켜진 시간"도 6시간 단위다. 12시간은 예측 두 번만큼 먼저라는 뜻이다.

**③ 기준을 고른 규칙: 주의 중 85% 이상은 실제로 열화 중인 설비, 그 안에서 가장 낮은 기준**

근거는 **현장 대응 방식**이다. 현장에서는 주의를 받으면 **일단 장비 상태를 확인하고, 설비가 돌아가면 다음 정비 때 그 부분까지 함께 정비한다.**
- 주의 때문에 설비를 세우지도, 바로 부품을 발주하지도 않는다. 그래서 **헛걸음의 비용은 점검 한 번**이다. 정비 인력은 충분하다(7-1절).
- 헛걸음으로 센 주의도 대부분 열화 직전 설비였다(④). 점검해서 다음 정비에 넣었다면 맞는 조치였을 가능성이 크다.
- 반대로 주의가 일찍 켜질수록 점검과 정비 계획에 쓸 시간이 늘어난다. 기준을 0.9에서 0.85로 낮추면 경보보다 12시간 이상 먼저 켜지는 고장이 29건에서 35건으로 늘어난다.
- **헛걸음 0을 요구하지 않는 이유**: 헛걸음 0을 요구하면 B의 기준이 0.98까지 올라가고, 경보보다 평균 2시간밖에 먼저 켜지지 않는다. 주의 단계를 둘 이유가 없어진다.
- **0.8 아래로 내리지 않는 이유**: 헛걸음이 0.85의 11번에서 0.8의 16번으로 늘어나는 데 비해 먼저 켜지는 시간은 거의 늘지 않는다(13.5 → 13.7시간). 헛걸음이 잦으면 현장이 주의를 무시하게 된다.

| 주의 정밀도 기준 | 주의 기준 | 헛걸음 | 경보보다 먼저 (평균) | 12시간 이상 먼저 |
|---|---|---|---|---|
| 0.8 | 0.34 | 16번 | 13.7시간 | 35건 |
| **0.85 (채택)** | **0.38** | **11번** | **13.5시간** | **35건** |
| 0.9 (처음 안) | 0.57 | 7번 | 10.9시간 | 29건 |
| 0.95 | 0.84 | 3번 | 6.7시간 | 12건 |

(방법 B, 학습 세트 교차검증. 학습 세트는 216개 상황 × 72시간 = 설비 648일이라, 헛걸음 11번은 설비 한 대 기준 약 두 달에 한 번이다.)

- **바뀐 과정 (기록)**: 처음에는 0.9(기준 0.57)로 정했고 그 검증 세트 결과(주의 정밀도 0.852)도 이미 봤다. 이후 현장 대응 방식을 근거로 0.85로 바꿨다. 바꾼 근거는 현장 대응이고, 검증 세트 숫자를 보고 바꾼 것이 아니다. 0.85의 검증 세트 결과는 바꾸기로 한 뒤 한 번 계산했다(⑤).
- 값은 `src/evaluate.py`의 `CAUTION_MIN_PRECISION`이다.
- 그림 `16_caution_주의임계값별_결과.png`: 위는 헛걸음 수, 아래는 경보보다 먼저 켜진 시간이다. 회색(A)은 헛걸음이 줄면 먼저 켜지는 시간도 같이 무너진다. 파랑(B)은 0.40~0.75에서 헛걸음 7~9번으로 평평하고, **0.38은 이 평평한 구간이 끝나 헛걸음이 늘기 시작하는 경계**다.

**④ 헛걸음 주의는 어떤 것이었나 (학습 세트 교차검증)**
- "열화 아닌 설비"로 센 주의 11번 중 **8번은 12시간 안에, 2번은 22시간 안에 실제로 열화가 시작됐다.**
- 끝까지 멀쩡한 설비에 켜진 주의는 1번이다(S0158).
- 그래도 정답상 열화 구간 밖이라 헛걸음으로 셌다. 결과를 좋게 보이려고 기준을 느슨하게 바꾸지 않았다.

**⑤ 검증 세트 (교차검증에서 정한 모델·기준 그대로, 한 번 확인)**

| | 학습 세트 교차검증 | 검증 세트 |
|---|---|---|
| 열화 감지 AP | 0.977 | 0.986 |
| 주의 정밀도 | 0.859 (78번 중 67번) | **0.774** (31번 중 24번) |
| 주의로 감지한 점진 고장 | 45/45 | 14/14 |
| 첫 주의: 고장까지 남은 시간 (중앙값) | 35.25시간 | 35.25시간 |
| 경보보다 먼저 켜진 시간 (평균 / 중앙값) | 13.5 / 12시간 | 12.4 / 12시간 |
| 경보보다 12시간 이상 먼저 켜진 고장 | 35/45 | 10/14 |

- **준비 시간은 교차검증과 거의 같게 나왔다.** 14건 모두 경보보다 6~24시간 먼저 주의가 켜졌다.
- **주의 정밀도는 목표 0.85에 못 미쳤다(0.774).** 헛걸음 7번 중 4번(S0234, S0248 두 번, S0254)은 열화 시작 0.75~7시간 전이었다. **나머지 3번(S0227 두 번, S0229)은 끝까지 열화가 없던 정상 설비였다.** 기준 0.38이 ③의 경계에 있어, 새 데이터에서 확률이 조금만 흔들려도 헛걸음이 늘어난 것으로 본다.
- 현장 대응으로 보면 이 3번은 **멀쩡한 설비를 한 번씩 점검한 것**이다. 검증 세트(설비 216일)에서 헛걸음 7번은 설비 한 대 기준 약 한 달에 한 번이다.
- 검증 세트를 보고 기준을 다시 고르지는 않았다. 헛걸음이 현장에서 부담이 되면 0.9(기준 0.57)로 되돌리는 것이 대안이다. 이때 검증 세트 정밀도는 0.852, 경보보다 먼저 평균 9시간이었다.
- 그림 `17_caution_검증_고장별_주의경보타임라인.png`: 보라 띠가 진단상 열화 구간이다. 노란 점(주의)이 띠가 시작되는 곳 근처에서 켜지고, 빨간 점(경보)이 뒤를 잇는다.

**⑥ 이 결과의 한계**
- 예측이 6시간 간격이라 주의가 얼마나 먼저 켜지는지도 6시간 단위로만 알 수 있다.
- 조달 기간 데이터가 없어 12시간 정도 더 얻는 것이 충분한지는 알 수 없다. 7-2절대로 예측으로 얻는 준비 시간은 열화 기간(중앙값 36시간)을 넘을 수 없다.
- 헛걸음의 비용(점검 한 번)은 현장 경험에서 온 가정이다. 데이터에는 점검 비용이 없다.
- 대시보드에는 주의 단계와 부품 소요 예측을 넣었다(`app/dashboard.py`, 시연용). 부품 소요는 "경보·주의 설비마다 두 부품"으로 센 단순 계산이다.

### 7-6. 이 제안의 한계

- 이 데이터에는 **재고와 조달 기간 정보가 없다.** 7-4는 정비 기록과 현장 경험을 합친 운영 제안이고, 데이터로 검증한 결과가 아니다.
- 합성 데이터라 고장이 실제보다 훨씬 자주 난다(고장 상황을 일부러 많이 넣은 데이터). 교체 횟수를 실제 재고량으로 쓰면 안 되고, **밸브와 진동장치의 비율(약 2:1)** 정도만 참고한다.
- 주의 단계로 얻는 약 12시간이 실제 조달에 충분한지는 데이터로 알 수 없다.

## 8. 테스트 세트 예측

- **방법**: 검증 세트에서 평가한 모델을 그대로 쓴다(학습 세트로 학습, 임계값 0.67, 보정값도 학습 세트에서 정한 값). 평가하지 않은 모델은 내보내지 않는다는 원칙이다. 주의 단계(7-5절)도 같은 원칙으로 함께 예측했다.
- **예측 시점**: 테스트 세트에는 정답 파일이 없어 시점을 직접 만든다. 0~66시간 6시간 간격에서 정비 중인 시점을 뺀다. 이 규칙은 학습·검증 세트에서 정답 파일의 `AT_RISK=1` 시점과 **3,345개 모두 일치**한다.

| 항목 | 값 |
|---|---|
| 시나리오 / 예측 시점 | 72개 / 833개 |
| 경보 | 83개 시점 (10.0%) |
| 경보가 한 번이라도 난 시나리오 | 18개 |
| 경보가 아닌 주의 시점 | 83개 |

- 경보 비율이 검증 세트와 비슷해, 테스트 세트의 데이터가 크게 달라지지 않았다고 본다.

## 10. 결론과 남은 과제

**결론**
- 센서 데이터만으로 **신호가 있는 고장은 하루 전후에 빠짐없이 미리 알 수 있다.** 기준 예제보다 순위 능력이 높고 2시간 더 일찍 알렸다.
- 성능의 대부분은 알고리즘이 아니라 **데이터를 이해하고 만든 특징**에서 나왔다. 학습 없이 네 신호 Z-score 평균만 써도 기준 예제보다 나았다.
- 평가에서는 **정답이 만들어진 방식**까지 의심해야 한다. 관측 창의 끝 때문에 생긴 착시가 이전 모델의 숫자를 부풀리고 있었고, 정답이 있는 시점만 보는 평가로는 드러나지 않았다.
- 실제 효과는 두 가지에 달려 있다. **원인 부품을 가려낼 수 있는가**, 그리고 **부품을 제때 확보할 수 있는가**다. 예측은 준비 시간을 주지만 이 둘을 대신하지는 못한다.

> 분석 범위: **학습 세트 216개 시나리오**. 검증·테스트 세트는 EDA에서 보지 않았다.

## A-1. 데이터와 지켜야 할 규칙

**사용하는 파일**

| 종류 | 파일 | 내용 | 크기 |
|---|---|---|---|
| 원자료 | `casting` | 연주 센서, 5초 간격 | 1,866만 행 (시나리오당 51,840행) |
| 정비 이력 | `maintenance`, `calendar` | 정비 기록, 정기수리 계획 | 수백 행 |
| 조업 이벤트 | `events` | 운전조건 변경 | 수천 행 |

| 정답 | `diagnostics` | 상태 구간(정상·열화·고장·정비), 원인 | — |

**지켜야 할 규칙**
1. **분할**: EDA와 특징 설계는 학습 세트로만 한다. 검증 세트 그래프를 보고 특징을 고르지 않는다.
2. **정답 열**(`labels`, `diagnostics`, `targets`의 열)은 특징으로 쓰지 않는다. EDA에서는 비교 대상을 나누는 데만 쓴다.
3. **예측 시점 이후 정보**(센서·정비)는 쓰지 않는다.
4. **검열된 정답**(관측이 끝나 결과를 알 수 없는 시점)은 0으로 채우지 않고 뺀다.

| **변화량 `_D`** | 정비 후 재가동할 때마다 첫 2시간 중앙값을 기준으로 잡고, 그 뒤 값에서 뺀다 | 시나리오마다 기준 수준이 다르다(E3). 첫 2시간은 기준을 잡는 시간이라 비교에서 뺀다 |
| **정상 구간** | 고장 원인이 없는 정상 시나리오 155개의 1시간 구간 (재가동 후 첫 2시간 제외) | 오경보가 어느 정도 나는지 보는 비교군 |
| **고장 전 구간** | 고장 시나리오에서 고장까지 남은 시간(HTF)이 정해진 범위인 1시간 구간. 고장과 같은 운전 구간 안만 | 사이에 정비가 끼면 다른 상태라 섞지 않는다 |
| **정상 범위 경계** | 정상 구간 값의 95% 분위수 (`OSC-STK`는 작아지는 쪽이라 5% 분위수) | 정상인데 경계를 넘는 비율이 정의상 5%다 |
| **표준화 점수 `Z`** | (값 − 정상 중앙값) × 방향 ÷ (정상 경계 − 정상 중앙값). 0 = 정상 중앙값, 1 = 정상 경계 | 단위가 다른 네 신호를 같은 잣대로 더하려고 |
| **점진 / 돌발 고장** | 고장 직전에 진단의 열화(`degraded`) 구간이 이어져 있으면 점진, 없으면 돌발 | 진단 정답은 고장의 성격을 나누는 데만 쓰고 특징으로는 쓰지 않는다 |
| **감지 리드타임** | 고장 직전 1시간부터 거꾸로, 조건(예: 신호 2개 이상이 경계를 넘음)이 **끊기지 않고** 이어진 시간 | "언제부터 계속 이상했나"를 잰다. 한 번 튄 값은 세지 않는다 |
| **AUC** | 고장 전 구간과 정상 구간의 값을 섞어 줄 세웠을 때, 고장 전 구간이 위에 올 확률. 0.5 = 구분 못 함, 1 = 완전 구분 | 임계값을 정하지 않고 신호의 세기만 비교한다 |

## A-4. 근거 E1~E12

### E1. 데이터는 깨끗하다

- **주장**: 별도 정제 없이 써도 된다. 결측과 정지에는 이유가 있다.
- **어떻게 쟀나**: 학습 세트 216개 시나리오의 원자료 1,119만 행에서 행 수, 시각 간격, 중복, 결측, 정지 구간을 확인했다.
- **결과**

| 항목 | 결과 |
|---|---|
| 시나리오당 행 수 | 216개 모두 51,840행 (= 72시간 × 720행) |
| 5초 간격이 아닌 곳 / 중복 시각 | 0 / 0 |
| 결측 | `MLD-LVL`만 648행 = 시나리오당 3행. 모두 같은 시각(23.6h, 47.3h, 70.9h)이고 `QUALITY_FLAG=missing`과 정확히 일치 |
| 정지(`RUNNING=0`) | 정지 구간 73개 모두 진단의 정비(`maintenance`) 또는 고장(`failed`) 구간과 일치. 정비 없이 멈춘 적은 없다 |

- **반론·한계**: 합성 데이터라 실제 설비보다 깨끗하다. 실제 데이터에서는 이 단계가 훨씬 길어진다.
- **재현**: 1-1 ~ 1-5

### E2. 고장은 정비 기록의 `FAILURE_DT`로 센다

- **주장**: 진단 정답의 `failed` 구간만 세면 고장을 대부분 놓친다.
- **어떻게 쟀나**: 진단의 `failed` 구간이 있는 시나리오와, 정비 기록에 `FAILURE_DT`가 있는 시나리오를 비교했다.
- **결과**

| 기준 | 고장 시나리오 |
|---|---|
| 진단 `failed` 구간 | 6개 |
| 정비 기록 `FAILURE_DT` | **49개 (고장 51건, 복구 정비 `repair` 51건과 일치)** |

- **이유**: 대부분 고장 즉시 복구 정비가 시작된다. 그래서 진단에는 "열화 → 정비"로만 기록되고, 고장과 복구 사이에 틈이 있을 때만 `failed` 구간이 생긴다.
- **재현**: 1-7

### E3. 절대값이 아니라 변화량을 봐야 한다

- **주장**: 시나리오마다 센서의 기준 수준이 달라서, 절대값으로는 "이 값이면 이상"이라고 말할 수 없다.
- **어떻게 쟀나**: 센서마다 시나리오 평균의 표준편차(시나리오 간 차이)를 시나리오 안 표준편차의 중앙값(시나리오 안 변동)으로 나눴다.
- **결과**

| 센서 | 시나리오 간 ÷ 시나리오 안 |
|---|---|
| `OSC-STK` | **12.8배** |
| `CONTROL_DELAY` | **6.8배** |
| `WD-LOD` | 1.1배 |
| `MLD-LVL` | 1.0배 |
| `LOAD` | 0.05배 |

- 예를 들어 `OSC-STK`는 시나리오끼리의 차이가 한 시나리오 안에서 열화로 생기는 변화보다 훨씬 크다. 절대값으로 경계를 정하면 원래 값이 낮은 시나리오는 늘 이상으로, 높은 시나리오는 늘 정상으로 나온다.
- **결정**: 운전 구간 첫 2시간을 기준으로 한 **변화량(`_D`)**을 쓴다(A-3).
- **재현**: 1-2

### E4. 열화 신호는 4개다

- **주장**: `MLD-LVL` 진폭, `CONTROL_DELAY`, `WD-LOD`(보정)는 커지고 `OSC-STK`는 작아진다. 고장 24~36시간 전부터 정상과 갈린다. `MLD-LVL` 평균은 신호가 없다.
- **어떻게 쟀나**: 원인별로 고장 전 구간을 시간대(0~6h, 6~12h, 12~24h, 24~36h)로 나눴다. 시간대마다 변화량 `_D`가 정상 구간과 얼마나 갈리는지 AUC를 계산했다.
- **결과** (AUC. `OSC-STK`는 작아지는 신호라 1 − AUC로 바꿔 적었다)

| 신호 | 방향 | 고장 전 0~6시간 | 고장 전 24~36시간 |
|---|---|---|---|
| `MLD-LVL` **진폭** | 커짐 | 0.95~0.98 | 0.90~0.95 |
| `CONTROL_DELAY` | 커짐 | 0.94~0.99 | 0.91~0.93 |
| `OSC-STK` | 작아짐 | 0.93~0.95 | 0.80~0.86 |
| `WD-LOD` (보정) | 커짐 | 0.90~0.98 | 0.80~0.91 |
| `MLD-LVL` 평균 | — | 0.46~0.55 | 0.52~0.59 |

(범위는 원인 세 가지 friction·sticking·control-delay의 최솟값~최댓값)

- **그림** `02_eda_고장전_센서변화량.png`: 고장 시각에 맞춰 정렬한 변화량이다. 파란 선(고장 시나리오 중앙값)이 회색 띠(정상 5~95%)를 벗어나는 시점을 보면 된다. 네 신호는 고장 36시간 전쯤부터 띠를 벗어나고, `MLD-LVL_D`(평균) 행만 끝까지 띠 안에 있다.
- **반론·한계**: AUC는 신호의 세기를 보여 줄 뿐 모델 성능이 아니다. 같은 시나리오의 시간 구간끼리는 독립이 아니라서 실제보다 좋게 보일 수 있다. 실제 성능은 본문 4절로 판단한다.
- **재현**: 6-4, 6-5

### E5. `WD-LOD`는 절편 보정 비율로 보정한다

- **주장**: `WD-LOD`는 부하(`LOAD`)에 따라 크게 움직여서 보정이 필요하다. `(WD-LOD − 3.06) / LOAD`가 세 방식 중 가장 좋다.
- **어떻게 쟀나**: 정상 시나리오 155개마다 `WD-LOD = 절편 + 기울기 × LOAD`를 맞춰 봤다. 기울기가 시나리오마다 79~126으로 달랐다(중앙값 106). 그래서 세 가지 보정을 비교했다.
  - **부하 상관**: 보정 후에도 부하와 같이 움직이는지. 0에 가까울수록 좋다.
  - **신호/잡음**: 고장 전 변화량의 중앙값 ÷ 정상 변화량의 폭(5~95%). 클수록 좋다.
- **결과**

| 방식 | 부하 상관 | 신호/잡음 0~6h | 신호/잡음 24~36h | AUC 24~36h |
|---|---|---|---|---|
| A. 공통 기울기 차감 `WD-LOD − 공통 기울기 × (LOAD − 평균)` | 0.21 | 1.74 | 0.56 | 0.837 |
| B. 비율 `WD-LOD / LOAD` | −0.66 | 2.17 | 0.70 | 0.829 |
| **C. 절편 보정 비율 `(WD-LOD − 3.06) / LOAD`** | **−0.01** | **2.33** | **0.80** | **0.847** |

- A는 시나리오마다 다른 기울기를 하나로 빼서 부하 주기가 남고, B는 절편을 무시해 반대 방향으로 부하가 남는다. C는 부하 영향이 거의 사라진다. 절편 3.06은 정상 시나리오 절편의 중앙값이다.
- **그림** `03_eda_WD-LOD_부하보정비교.png`: 기울기가 공통값과 가장 다른 정상 시나리오에서 세 방식의 변화량을 비교한다. A, B에는 부하를 따라 오르내리는 물결이 남고 C는 평평하다.
- **나머지 신호**: `OSC-STK`, `CONTROL_DELAY`는 시나리오 간 기울기 차이가 작아 A(공통 기울기 차감)로 충분했다.
- **재현**: 6-6

### E6. 24시간 앞서 잡을 수 있는 고장은 약 76%다

- **주장**: 학습 세트 고장 51건 중 39건은 센서가 24시간 이상 앞서 이상을 보인다. 나머지 12건은 어떤 모델로도 24시간 앞서 잡기 어렵다.
- **어떻게 쟀나**
  1. 고장을 점진(45건)과 돌발(6건)로 나눴다(A-3 정의).
  2. 고장마다 **신호 2개 이상이 정상 범위 경계를 넘은 상태가 고장까지 끊기지 않고 이어진 시간**(감지 리드타임)을 쟀다.
  3. 감지 리드타임이 24시간 이상인 고장을 셌다.
- **결과**

| | 진단 리드타임 (열화 시작 → 고장) | 감지 리드타임 중앙값 | 24시간 이상 앞서 감지 |
|---|---|---|---|
| 점진 고장 45건 | 14.5~54.5시간 (중앙값 36) | 36시간 | **39/45** |
| 돌발 고장 6건 | 열화 구간 없음 | 0시간 | **0/6** |
| **합계 51건** | | | **39/51 = 76%** |

못 잡는 12건:

| 구분 | 고장 | 이유 |
|---|---|---|
| 돌발 고장 6건 | S0004, S0050, S0082, S0125, S0148, S0174 | 고장 직전까지 네 신호가 모두 정상 범위 안에 있다. 신호 2개 이상이 벗어난 채 이어진 시간은 5건이 0시간, S0004가 1시간이다 |
| 열화가 짧은 점진 고장 6건 | S0086 (2건), S0153 (2건), S0002, S0080 | 감지 리드타임 15~22시간. 열화 자체가 14.5~24시간이라 그보다 앞선 신호가 없다 |

- 신호 하나씩 보면 24시간 이상 앞서 감지되는 점진 고장은 `MLD-AMP` 40건, `CONTROL_DELAY` 36건, `OSC-STK` 32건, `WD-LOD` 31건이다.
- **그림** `04_eda_리드타임_진단vs센서.png`: 점 하나가 점진 고장 하나다. 가로축은 진단상 열화 시작부터 고장까지, 세로축은 센서 감지부터 고장까지 걸린 시간이다. 점이 대각선 근처에 몰려 있다 = **센서가 열화 시작을 거의 바로 잡는다.** 빨간 선(24시간) 아래 점 6개가 못 잡는 점진 고장이다.
- **반론·한계**
  - "신호 2개 이상, 95% 경계"는 하나의 기준이다. 기준을 바꾸면 39건이 조금 달라질 수 있다. 그래서 정확한 상한이 아니라 **추정치**다.
  - 다만 열화가 짧은 6건은 열화 시작 자체가 고장 24시간 안이고, 돌발 6건은 신호가 아예 없다. 기준을 바꿔도 이 12건을 24시간 앞서 잡기는 어렵다.
  - 모델 평가의 "고장 감지"는 기준이 다르다(교체에 필요한 4시간 전까지만 경보하면 감지). 그래서 본문 4절의 감지율이 76%보다 높게 나온다.
- **재현**: 7-1

### E7. 정상 시나리오의 짧은 혹은 고장 전 이상과 길이로 구분된다

- **주장**: 정상인데 신호가 잠깐 튀는 "혹"이 있다. 하지만 짧아서 고장 전 이상과 겹치지 않는다.
- **어떻게 쟀나**: 정상 시나리오 155개에서 신호 2개 이상이 동시에 경계를 넘은 연속 구간(혹)을 모두 찾아 길이를 쟀다. 점진 고장 전 연속 이상(E6의 감지 리드타임)의 길이와 비교했다.
- **결과**

| | 개수 | 길이 |
|---|---|---|
| 정상 시나리오의 혹 | 103개 (155개 중 57개 시나리오) | 대부분 1~3시간, **최장 10시간** |
| 점진 고장 전 연속 이상 | 45건 | **최단 15시간** |

| 지속 조건 | 남는 정상 혹 | 남는 점진 고장 |
|---|---|---|
| 3시간 이상 | 18/103 | 45/45 |

- **그림** `05_eda_정상혹_vs_고장전_지속시간.png`: 회색(정상 혹)은 0~10시간에, 파랑(고장 전 이상)은 15시간 이상에 있어 겹치지 않는다.
- **반론·한계**: 지속 조건을 걸면 그만큼 경보가 늦어진다(6시간 조건 → 6시간 늦게 경보). 모델에서는 조건을 따로 걸지 않고, 지속 시간(`PERSIST_H`)을 특징으로 넣어 모델이 판단하게 했다(결정 G).
- **재현**: 7-3

### E8. 네 신호의 평균 점수가 오경보를 크게 줄인다

- **주장**: 네 신호는 정상일 때 따로 흔들리고 고장 전에는 함께 오른다. 그래서 평균을 내면 정상 잡음은 상쇄되고 고장 신호는 남는다.
- **어떻게 쟀나**
  1. 상관: 정상 구간과 고장 전 구간에서 신호끼리의 상관을 계산했다.
  2. 결합 점수: 네 신호를 표준화 점수(`Z`, A-3)로 바꾼 뒤 평균·최댓값·두 번째로 큰 값을 만들었다. 각 점수가 1(정상 경계)을 넘는 비율을 정상 구간과 고장 전 24~36시간 구간에서 비교했다.
- **결과**

| 상관 | 값 |
|---|---|
| 정상 구간에서 신호끼리 | 0.00~0.04 (거의 독립). 예외: `CONTROL_DELAY`와 `OSC-STK` 0.52 |
| 고장 전, 한 시나리오 안에서 시간에 따라 | 0.83~0.97 (함께 오름) |
| 고장 직전, 시나리오끼리 | 0.35~0.55 (시나리오마다 강하게 반응하는 신호가 다름) |

| 점수 | 정상 구간에서 경계 초과 (오경보 쪽) | 고장 전 24~36시간에 경계 초과 (감지 쪽) |
|---|---|---|
| 신호 하나 (각각) | 5.0% | 62~84% |
| **네 신호 평균** | **0.4%** | **79%** |
| 두 번째로 큰 값 | 1.7% | 77% |
| 최댓값 | 18.2% | 86% |

- 평균 점수는 오경보 쪽 비율을 신호 하나의 1/12로 줄이면서, 감지 쪽 비율은 가장 좋은 신호(`MLD-AMP` 84%)에 가깝게 유지한다.
- `MLD-AMP`가 가장 먼저 벗어난다: 점진 고장 45건 중 44건(동률 포함), 감지 리드타임 중앙값 39시간(다른 신호 30~35시간).
- **그림** `08_eda_신호간_상관.png`
- **결정**: 네 신호를 모두 쓰고, 평균 점수(`SCORE`)를 핵심 특징으로 둔다. 이 점수가 본문의 Z-score 기준 모델이다.
- **재현**: 9-1 ~ 9-3

### E9. 센서로 고장 원인은 구분할 수 없다

- **주장**: 원인(마찰·고착·제어 지연)과 부품(진동장치·밸브)에 따라 센서 반응이 다르지 않다. 그래서 원인 진단은 범위에서 빼고 **원인과 상관없이 24시간 안 고장 여부**를 예측한다.
- **어떻게 쟀나**
  1. 열화 구간 82개(시나리오 54개)마다 끝나기 직전 6시간의 네 신호 `Z` 평균을 "반응 지문"으로 만들었다. 세기(Z 그대로)와 비율(Z의 합을 1로 맞춘 값) 두 가지다.
  2. 이 지문으로 원인·부품을 맞히는 로지스틱 회귀를 **시나리오 하나씩 빼고 학습해 빠진 시나리오를 맞히는 방식**(leave-one-out)으로 평가했다.
  3. 정확도를 "가장 흔한 원인으로 모두 찍었을 때"의 정확도(기준선)와 비교했다.
- **결과**

| 맞힐 대상 | 특징 | 정확도 | 기준선 (찍기) |
|---|---|---|---|
| 원인 (3가지) | 세기 / 비율 / 세기 + 비율 | 0.39 / 0.35 / 0.42 | 0.37 |
| 부품 (2가지) | 세기 / 비율 / 세기 + 비율 | 0.73 / 0.70 / 0.72 | 0.72 |

- 원인과 부품은 1:1로 묶여 있다: 마찰 = 진동장치, 고착·제어 지연 = 밸브.
- **그림** `09_eda_원인별_반응지문.png`: 세 원인의 상자가 모든 신호에서 겹친다.
- **반론·한계**: 네 신호 요약값으로는 구분이 안 된다는 뜻이다. 5초 원자료의 파형·주파수로도 확인했지만 구분되지 않았다(본문 6-1절). 원인을 모르면 비용 평가에서 "어느 부품을 바꾸나"가 문제가 된다(결정 C).
- **재현**: 10-1 ~ 10-3

### E10. 정비해도 신호는 처음 수준까지 돌아가지 않는다

- **주장**: 정비 직후 신호는 내려가지만 시나리오 처음 수준까지는 아니다. 부분 정비 뒤에는 곧 다시 열화된다.
- **어떻게 쟀나**
  - 회복률 = (정비 직전 − 정비 직후) ÷ (정비 직전 − 시나리오 처음 수준). 1이면 처음 수준으로 완전히 돌아간 것이다. 정비 직전에 신호가 정상 경계 이상 벗어나 있던 경우만 계산했다.
  - 부분 정비 6건은 정비가 끝난 뒤 다음 열화 시작과 고장까지의 시간을 쟀다.
- **결과**

| 정비 유형 | `MLD-AMP` | `CONTROL_DELAY` | `WD-LOD` | `OSC-STK` |
|---|---|---|---|---|
| 부분 정비 | 0.76 | 0.84 | 0.79 | 0.71 |
| 고장 후 복구 | 0.82 | 0.87 | 0.81 | 0.86 |
| 정기 교체 | 0.84 | 0.84 | 0.93 | 0.81 |

- 부분 정비 6건은 모두 **0~4시간 만에 다시 열화**가 시작됐고 **25~33시간 뒤 고장** 났다. 현장에서는 제대로 된 부분 정비 뒤 재고장이 드물어, 이 성질은 합성 데이터의 생성 규칙으로 본다(본문 6-1절 ④).
- **그림** `10_eda_부분정비_전후신호.png`: 부분 정비 전후 24시간의 신호를 처음 수준 기준으로 그렸다. 정비 뒤 잠깐 내려갔다가 곧 다시 오른다.
- **결정**: 재가동 기준 변화량(`_D`)만 쓰면 정비 직후가 0으로 초기화돼 "다 나았다"처럼 보인다. 그래서 **처음 수준 대비 변화량(`_F`)**과 **정비 이력**(마지막 정비 유형, 경과 시간)을 함께 쓴다(결정 F).
- **재현**: 11-2, 11-3

### E11. 운전조건은 센서에 영향이 거의 없다

- **주장**: 운전조건 코드(0·1·2)는 특징으로 쓰지 않는다.
- **어떻게 쟀나**: 운전조건 일정을 시나리오별로 확인하고, 정상 시나리오에서 운전조건별 센서 평균 차이를 효과 크기(차이 ÷ 표준편차)로 쟀다.
- **결과**
  - 216개 시나리오 **모두 같은 일정**이다: 0시간 0 → 12시간 1 → 24시간 2 → 36시간 0 → 48시간 1 → 60시간 2. 그래서 운전조건 코드는 경과 시간과 같은 정보다.
  - 효과 크기: `WD-LOD` 0.09, `OSC-STK` 0.09, `CONTROL_DELAY` 0.20, `MLD-AMP` 0.30. 보통 0.2 아래면 무시할 만하다고 본다. `MLD-AMP`도 운전조건 간 차이는 0.004로, 고장 전 변화(그림 `02`에서 0.3~1.8)에 비하면 매우 작다.
- **그림** `06_eda_운전조건별_정상변화량.png`

### E12. 정답 `RISK_24H`에는 "이른 경보" 시점이 생긴다

- **주장**: 신호가 크게 벗어나 있는데 정답이 0인 시점이 있다. 이 시점의 경보는 진짜 오경보와 성격이 다르다.
- **어떻게 쟀나**: 고장 원인이 있는데 72시간 안에 고장이 안 난 시나리오 12개를 정비 기록과 정답으로 확인했다.
- **결과**
  - 11개는 열화 중에 **정기 교체(`replace`)**가 들어가 고장이 막혔다. 1개(S0016)는 71시간에 열화가 시작돼 관측이 끝났다.

## B-3. 무엇을 세나

**시점 단위 혼동행렬** (정답을 알 수 있는 예측 시점마다)

| | 실제 24시간 안 고장 (1) | 24시간 안 고장 없음 (0) |
|---|---|---|
| **경보 냄** | **TP** 맞은 경보 | **FP** 오경보 → 이른 경보 / 진짜 오경보로 나눔 |
| **경보 안 냄** | **FN** 놓친 고장 → 돌발 / 점진 고장으로 나눔 | **TN** 맞게 조용함 |

- 정밀도(Precision) = TP / (TP + FP): 경보가 났을 때 실제로 24시간 안에 고장 난 비율
- 재현율(Recall) = TP / (TP + FN): 24시간 안 고장 시점 중 경보를 낸 비율
- F1 = 2 × 정밀도 × 재현율 / (정밀도 + 재현율)
- AP: 임계값을 모두 바꿔 가며 본 정밀도-재현율 곡선의 넓이. **임계값과 상관없는 순위 능력**이라 모델 비교에 쓴다
- **이른 경보**: 정답은 0이지만 관측 기간 안에 고장 예정(`RUL_EVENT=1`)인 시점의 경보 (E12)
- **돌발 고장**: 고장 직전 열화 구간이 없는 고장. 신호가 없어 미리 잡을 수 없다 (E6)

**고장 단위** (고장마다)
- **감지**: 같은 운전 구간 안에서 고장 **4시간 전까지** 경보가 한 번이라도 났으면 감지. 4시간은 정기 교체에 걸리는 시간이다.
- **리드타임**: 가장 이른 경보부터 고장까지의 시간.

**미확정 경보** (본문 2-2절 1번)
- 관측이 끝나 정답을 알 수 없는 시점에서도 실제 운영이라면 경보가 울리고 교체가 일어난다. 그래서 이런 시점의 경보를 따로 센다.
- 이미 평가된 경보와 이어지지 않는 경보 묶음만 센다. 맞은 경보인지 알 수 없으므로 비용은 범위로 낸다(필요한 교체였으면 40, 불필요했으면 48, 두 부품 교체 기준).
- 이 경보들이 실제로 열화 중인 설비에 울렸는지는 진단 정답으로 확인한다(평가 해석에만 쓰고 모델에는 쓰지 않는다).

**비용** (데이터셋 `toolkit/targets.md`의 규칙, 단위는 점수)

| 항목 | 점수 |
|---|---|
| 부품 교체 | 12 |
| 고장 후 복구 | 30 |
| 정지 시간 | 1시간당 2 (교체 4시간, 복구 8시간) |
| 고장 벌점 | 20 |
| 불필요한 정비 벌점 (멀쩡한 부품 교체) | 8 |

경보가 나면 바로 교체한다고 보고, 고장 단위로 시간 순서를 따라가며 계산한다. 센서로 원인 부품을 알 수 없어서(E9) 부품 선택 가정을 세 가지로 나눈다.

| 상황 | 부품 맞힘 (상한) | **두 부품 모두 교체 (대표)** | 하나 찍기 (최악) |
|---|---|---|---|

## B-4. 팀 결정 A~G의 근거 (모두 확정, 2026-10-13. D의 값은 개정으로 바뀜)

결정마다 **무엇을 정하는지 → 선택지 → 결정 → 근거 → 한계** 순서로 적었다. 요약 표는 본문 2-1절에 있다.

### A. 이른 경보: 오경보로 세고, 따로 보고

**무엇을 정하나**
경보가 울렸는데 정답(`RISK_24H`)은 0인 시점 중에는, 고장이 24시간보다 **뒤에** 예정된 시점이 있다. 실제로는 열화 중인 설비를 일찍 알아챈 것이다. 이것을 오경보로 셀지 정한다.

판정 방법 (경보가 울린 시점마다):

| 정답 `RISK_24H` | 고장 예정 `RUL_EVENT` | 판정 |
|---|---|---|
| 1 (24시간 안 고장) | — | 맞은 경보 (TP) |
| 0 | 1 (관측 기간 안에 고장 예정, 24시간보다 뒤) | **이른 경보** → 오경보(FP)로 센다 |
| 0 | 0 (관측이 끝날 때까지 고장 예정 없음) | 진짜 오경보 (FP) |

- `RUL_EVENT`는 정답 파일의 열이라 평가에만 쓰고 특징으로는 쓰지 않는다.
- `RUL_EVENT`는 "이후 정비를 더 안 한다면" 기준이라, 정기 교체로 고장이 막힌 설비도 교체 전에는 고장 예정(1)이다(E12).

**선택지와 결과** (검증 세트)

| 선택지 | 정밀도 | 장단점 |
|---|---|---|
| ① 오경보로 센다 | 0.753 | 정답 그대로라 가장 보수적. 하지만 일찍 알아챈 것까지 틀린 것으로 보인다 |
| ② 맞은 경보로 센다 | 0.986 | 현장 관점에는 맞지만, 정답 정의를 우리에게 유리하게 바꾼 셈이다 |
| **③ 오경보로 세고 따로 보고 (결정)** | **0.753** + 이른 경보 내역 | 숫자는 보수적으로, 의미는 따로 설명한다 |

**근거**
- 검증 세트 오경보 18개 중 **17개가 이른 경보**였다. 고장까지 24.5~45시간 남은 시점이었고, 16개는 실제로 고장 난 설비, 1개(S0270)는 정기 교체로 고장이 막힌 설비였다.
- 그래서 이 모델의 오경보는 대부분 "멀쩡한 설비를 세우는 경보"가 아니라 "조금 일찍 울린 경보"다. 본문 7절에서는 이를 부품 준비를 시작하는 신호로 쓰자고 제안했다.

**한계**
- 관측이 72시간에서 끝나서, 그 뒤에 고장 났을 설비도 `RUL_EVENT=0`으로 보인다. 그래서 진짜 오경보는 실제보다 **많게** 셀 수 있다(보수적인 방향). 실제 사례가 S0248이다(본문 4-2절).

### B. 돌발 고장: 대표 재현율에서 빼고, 따로 보고

**무엇을 정하나**
고장 중에는 열화 신호 없이 갑자기 나는 **돌발 고장**이 있다(고장 직전에 진단상 열화 구간이 없는 고장). 이것을 놓친 것을 재현율에 반영할지 정한다.

**근거: 돌발 고장은 어떤 모델로도 미리 잡을 수 없다**
- 학습 세트 돌발 고장 6건은 고장 직전까지 신호가 거의 정상 범위 안에 있었다. 신호가 2개 이상 벗어난 채 이어진 시간은 5건이 **0시간**, 1건(S0004)이 **1시간**뿐이다. 신호 하나만 봐도 길어야 4시간이다(E6). 교체에 4시간이 걸리니 미리 막을 수 없다.
- 신호가 없으니 모델을 아무리 바꿔도 잡을 수 없다. 돌발 고장을 재현율에 넣으면 **모델의 성능이 아니라 데이터의 한계**를 함께 재게 된다. 비교한 세 모델 모두 돌발 고장을 0/2 감지해서, 넣어도 모델 사이의 차이는 그대로다.

**선택지와 결과** (검증 세트)

| 재현율 | 우리 모델 | Z-score 기준 모델 | 기준 예제 |
|---|---|---|---|
| **점진 고장 기준 (대표, 결정)** | **0.887** | 0.823 | 0.903 |
| 돌발 고장 포함 (참고, 항상 함께 표기) | 0.786 | 0.729 | 0.800 |

**한계**
- 현장에서는 돌발 고장도 똑같이 설비를 세운다. 그래서 숫자를 뺄 뿐 숨기지 않는다. 모든 결과 표에 돌발 고장을 포함한 재현율을 함께 적는다.
- 돌발 고장은 예측이 아니라 예비품 확보 같은 다른 방법으로 대비해야 한다(본문 7절).

### C. 부품 선택: 경보가 나면 두 부품 모두 교체

근거와 숫자는 본문 6절(비용 비교)과 6-1절(5초 원자료·정비 기록 확인)에 있다.
- 센서로는 원인 부품을 알 수 없다. 1시간 요약(E9)이든 5초 원자료(6-1절)든 찍기 수준이다.
- "항상 밸브만" 같은 찍기 전략은 두 부품 교체보다 비싸다(944~968 vs 860).
- 정비 기록의 "직전이 부분 정비면 그 부품" 규칙은 현장 경험과 맞지 않아 쓰지 않는다(6-1절 ④).
- 현장 점검으로 부품을 가려낼 수 있으면 비용은 최대 500까지 내려간다. 주의 단계(7-5절)가 점검 시간을 벌어 준다.

### D. 임계값: 규칙은 그대로, 값은 0.76 → 0.67

**무엇을 정하나**
모델은 "24시간 안 고장 확률"을 낸다. 확률이 얼마 이상이면 경보를 울릴지 정한다. 낮추면 일찍 울리지만 오경보가 늘고, 높이면 오경보는 줄지만 늦게 울리거나 고장을 놓친다.

**결정 규칙** (팀 확정, 위에서부터 우선)
1. 신호가 있는 고장(점진 고장)은 **하나도 놓치지 않는다** — 놓치면 가장 비싸다(66점, 정지 8시간)
2. 멀쩡한 설비에 울리는 **진짜 오경보는 0** — 오경보가 잦으면 현장이 경보를 믿지 않는다
3. 1, 2를 지키는 범위에서 **가장 일찍** 울린다 — 부품 조달 시간을 최대한 확보한다

값이 0.76에서 0.67로 바뀐 이유의 쉬운 설명은 본문 2-2절에 있다.

**근거** (학습 세트 교차검증. 검증 세트는 보지 않고 정했다)

| 임계값 | 놓친 점진 고장 | 진짜 오경보 | 리드타임 중앙값 | |
|---|---|---|---|---|
| 0.50 | 0 | 3번 | 26.5시간 | 규칙 2 위반 |
| 0.66 | 0 | 1번 | 24.25시간 | 규칙 2 위반 |
| **0.67** | **0** | **0** | **23시간** | **세 규칙을 모두 만족하는 가장 낮은 값** |
| 0.76 (이전 값) | 0 | 0 | 22.5시간 | 같은 결과를 더 늦게 (규칙 3 위반) |
| 0.81 | 0 | 0 | 20시간 | 비용 최소, 더 늦게 |
| 0.85 이상 | 1~15건 | 0 | 19시간 이하 | 규칙 1 위반 |

- 더 낮추면 얻는 시간이 작다. 0.50까지 낮춰도 리드타임은 약 3.5시간 늘 뿐인데 진짜 오경보가 3번 생긴다. 신호 자체가 대부분 고장 36시간 전 이후에 나타나기 때문이다.
- 그림 `14_model_임계값별_경보결과.png`: 실선이 선택한 0.67, 점선이 비용 최소 0.81이다.

**왜 비용으로 고르지 않았나**
- 비용 규칙에는 **리드타임의 가치**(4시간 전에 울려도 30시간 전에 울려도 같은 20점), **부품 조달**(재고가 없을 때의 대기·긴급 조달), **실제 금액**이 없다. 그래서 늦게 울릴수록 이른 경보가 줄어 비용이 낮아지고, 비용 최소 기준은 0.81을 고른다.
- 즉 이 데이터로는 임계값 사이의 실제 비용 차이를 알 수 없다. 비용은 "아무것도 안 할 때보다 싸다"는 확인용으로만 쓴다.

**검증 세트에서 다른 임계값을 썼다면** (참고, 선택에는 쓰지 않음)

| 임계값 | 정밀도 | 재현율 (점진 고장 기준) | 놓친 점진 고장 시점 | 진짜 오경보 | 리드타임 중앙값 | 비용 (두 부품) |
|---|---|---|---|---|---|---|

| 0.72 (F1 최대) | 0.791 | 0.855 | 9 | 0 | 24시간 | 812 |
| 0.81 (비용 최소) | 0.847 | 0.806 | 12 | 0 | 18시간 | 772 |

- 검증 세트에서는 0.72가 더 좋아 보이지만, 검증 세트를 보고 임계값을 바꾸면 그 세트에 맞춘 결과가 된다. 학습 세트에서 정한 0.67을 그대로 쓴다.

### E. 시간을 세는 특징: 쓰지 않는다

**무엇을 정하나**
시간을 세는 특징이 두 개 있다.

| 특징 | 뜻 |
|---|---|
| `ELAPSED_H` 경과 시간 | **시나리오(72시간 관측 구간)가 시작된 뒤 지난 시간**. 예측 시점이 0, 6, …, 66시간이니 그 숫자가 그대로 특징이 된다 |
| `SEG_HOURS` 재가동 후 시간 | 마지막 정비 뒤 다시 돌기 시작한 지 지난 시간. **정비가 없던 시나리오에서는 경과 시간과 같은 값**이다 |

둘 다 설비 상태가 아니라 **데이터를 72시간씩 잘라 만든 관측 창 안에서의 위치**를 담는다. 처음에는 경과 시간만 뺐고, `SEG_HOURS`는 특징에 들어 있었다(본문 2-2절 5번).

**왜 후보였나**: 시간에 따라 24시간 안 고장 비율이 뚜렷이 달라진다 (학습 세트).

| 경과 시간 | 0h | 12h | 24h | 36h | 48h | 54h | 60h | 66h |
|---|---|---|---|---|---|---|---|---|
| 24시간 안 고장 비율 | 1% | 5% | 10% | 18% | 14% | **100%** | **100%** | **100%** |
| 시점 수 | 216 | 216 | 203 | 211 | 201 | 18 | 7 | 1 |

**근거: 쓰지 않는 이유**
1. **54시간 이후 100%는 관측 창이 만든 착시다.** 54시간 시점에서 "24시간 안 고장 없음(0)"을 확인하려면 78시간까지 봐야 하는데 관측은 72시간에서 끝난다. 그래서 0인 시점은 결과를 알 수 없어 빠지고 고장 시점(1)만 남는다. 시간을 세는 특징을 넣으면 모델이 **"오래 돌았으면 고장"**이라는 데이터 구조의 우연을 배운다.
2. **실제로 그 착시를 배웠다.** `SEG_HOURS`를 넣은 이전 모델(로지스틱 회귀)은 관측 끝(66시간)에서 신호가 거의 정상인 설비에도 경보를 울렸다. `SEG_HOURS` 하나가 위험도(로그 오즈)를 +3.37 올렸다. 학습 세트 교차검증에서 정답을 알 수 없는 시점의 경보를 세어 보면:

| 모델 (학습 세트 교차검증) | CV AP | 임계값 | 정답을 알 수 없는 구간의 경보 묶음 | 그중 진단상 **정상**인 시점 |
|---|---|---|---|---|
| 이전: 로지스틱 회귀, `SEG_HOURS` 포함 | 0.849 | 0.76 | 36 | **22개** |
| 로지스틱 회귀, `SEG_HOURS` 제외 | 0.830 | 0.69 | 15 | 2개 |
| **최종: 랜덤포레스트, `SEG_HOURS` 제외** | **0.837** | **0.67** | 12 | **0개** |

   - `SEG_HOURS`를 빼면 로지스틱 회귀의 AP가 0.849 → 0.830으로 내려간다. **이전 AP의 일부가 착시로 부풀려진 값**이었다는 뜻이다.
   - 정답이 있는 시점만 보는 평가(이전 "진짜 오경보 0")로는 이 문제가 보이지 않았다. 문제의 경보가 모두 정답을 알 수 없는 관측 끝부분에 있었기 때문이다.
3. **실제 설비에는 "시나리오 시작"이 없다.** 설비는 계속 돌아가고, 시나리오 시작은 데이터를 만든 쪽이 정한 관측 창의 시작일 뿐이다.
4. **운전조건과 같은 정보다.** 운전조건 일정이 모든 시나리오에서 같아서(12시간마다 0 → 1 → 2, E11) 운전조건 코드를 뺀 이유와 같다.
5. **최종 모델에는 넣어도 얻는 게 없다.**

| 특징 (랜덤포레스트, 학습 세트 교차검증) | AP |
|---|---|
| 경과 시간만 | 0.303 |
| 재가동 후 시간만 | 0.274 |
| 지금 특징 (28개) | 0.837 |
| 지금 특징 + 경과 시간 | 0.837 |
| 지금 특징 + 재가동 후 시간 | 0.838 |

**헷갈리기 쉬운 점**: **마지막 정비 뒤 지난 시간**(`H_SINCE_MNT`)도 시간을 세지만 남겼다(결정 F). 정비를 한 설비에만 값이 있어 관측 창의 위치와 같지 않고, 정비 뒤 재열화(E10)를 담는다. 최종 모델에서는 정답을 알 수 없는 구간의 경보가 모두 실제 열화 중인 설비였다(위 표).

### F. 정비 이력: 특징으로 쓴다

**무엇을 정하나**
예측 시점까지 끝난 정비 기록으로 만든 특징 5개(`N_MNT`, `H_SINCE_MNT`, `LAST_PARTIAL`·`LAST_REPAIR`·`LAST_REPLACE`, B-1)를 넣을지 정한다.

**근거 1: 정비 뒤에도 열화가 남는다** (E10)
- 어떤 정비도 신호를 처음 수준까지 되돌리지 못한다(회복률 0.71~0.93).
- 센서 변화량은 정비 후 재가동 때 0으로 다시 맞춰지므로, "직전에 어떤 정비를 했다"는 정보가 따로 있어야 정비 뒤 위험을 알 수 있다.

**근거 2: 세 모델 모두 성능이 오른다** (학습 세트 교차검증 AP)

| 모델 | 센서만 | 센서 + 정비 이력 |
|---|---|---|
| 로지스틱 회귀 | 0.823 | 0.830 |
| 랜덤포레스트 | 0.834 | **0.837** |
| 그래디언트 부스팅 | 0.823 | 0.828 |

- 이 데이터에서는 부분 정비 뒤 재고장이 반드시 일어나(E10), 정비 이력의 효과가 실제 현장보다 크게 나왔을 수 있다(본문 6-1절 ④).

**미래 정보는 쓰지 않는다**: 예측 시점까지 **끝난** 정비만 쓴다. 진행 중인 정비나 이후 계획은 쓰지 않는다(B-2).

### G. 지속 시간 조건: 걸지 않는다

**무엇을 정하나**
"확률이 기준을 넘은 상태가 일정 시간 이어져야 경보"라는 조건을 따로 걸지 정한다. 잠깐 튀는 신호에 울리는 오경보를 줄이려고 흔히 쓰는 방법이다.

**근거 1: 줄일 오경보가 없다**
- EDA에서는 정상 설비에서도 신호가 1~10시간 잠깐 벗어나는 "혹"이 103번 있었고, 6시간 조건을 걸면 4번으로 줄었다(E7). 그래서 후보였다.
- 그런데 모델에는 이미 **이상이 이어진 시간(`PERSIST_H`)과 네 신호 평균 점수**가 특징으로 들어 있어, 학습 세트 교차검증에서 조건 없이도 진짜 오경보가 0이다.

**근거 2: 걸면 잃기만 한다** — "6시간 간격 예측에서 2번 연속 경보일 때만 울림" 조건을 학습 세트 교차검증에 적용했다.

| | 점진 고장 감지 | 리드타임 중앙값 | 진짜 오경보 |
|---|---|---|---|
| **조건 없음 (결정)** | **45/45** | **23시간** | 0 |
| 2번 연속 조건 | 41/45 | 18.25시간 | 0 |

- 오경보는 그대로 0인데, 고장 4건을 놓치고 리드타임이 약 5시간 줄어든다. 부품 조달 시간이 빠듯하다는 현장 의견(본문 7절)과도 반대 방향이다.

## B-5. 모델·특징 묶음 선택 (학습 세트 교차검증)

- **어떻게 쟀나**: 모델 3개 × 특징 묶음 2개 = 6개 조합을 같은 교차검증(폴드마다 보정값을 다시 정함)으로 비교했다. 기준 예제와 Z-score 기준 모델도 같은 교차검증·같은 임계값 규칙으로 평가했다. **교차검증 AP**가 가장 높은 조합을 고른다.
